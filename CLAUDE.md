# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`aish` is a terminal AI agent (local Ollama model by default, cloud backends optional) that runs shell commands, edits files, and browses the web — with a mandatory user-approval gate on anything that mutates state. The README covers user-facing behavior thoroughly; this file covers what you need to change the code safely.

## Commands

```sh
uv run pytest                          # full test suite — no model/network needed
uv run pytest tests/test_agent.py      # one file
uv run pytest tests/test_agent.py -k compaction   # one test by keyword
uv run ruff check .                    # lint (also formats config: line-length 100)
uv run mypy                            # type check (CI-gated; config in pyproject.toml)
uv run aish                            # run from source
```

After changing code, the user's installed `aish` does NOT pick it up — uv freezes the wheel and caches it at the same version. Reinstall with:

```sh
uv tool install --force --reinstall --no-cache /path/to/aish
```

## Workflow: when to use a worktree

Before editing code, check `git status`. Work in a git worktree on a feature branch (via EnterWorktree) instead of this checkout when either:

- the change is **non-trivial** — a multi-file feature or refactor, not a small fix; or
- the tree is **not clean with changes you didn't make** — the user or another session is mid-work in this checkout.

Merge back to main after tests pass, then remove the worktree. Trivial fixes on a clean tree go directly in this checkout. The reinstall/ship step (`uv tool install ...`) always runs from this main checkout after merge — never from a worktree path.

## Architecture

The core invariant: **the model never executes anything directly.** Backends only return structured tool-call requests; `Agent._dispatch()` in `agent.py` is the single execution point, and `run_command` is unreachable there unless the `approve()` callback returns the (possibly user-edited) command.

Data flow: `cli.py` (REPL/argv, slash commands, rendering) constructs an `Agent` with a chat callable from `backends.py` and an `approve` callback, then calls `agent.run_task()`. The agent loops: model proposes tool calls → `_dispatch()` executes them (gated) → results appended → repeat until a final answer. Approver verdicts: `True`/edited-string approve, `None`/`False` deny, `Blocked(reason)` (denylist — unapprovable), `Denied(comment)` and `Approved(comment, command=None)` — both web-card-only (CLI approvers still return bool/str/None), and both constructed ONLY when the user typed a comment. **A comment makes approve and deny mean opposite things (issue #81):** `Denied(comment)` = STOP — the action is denied, the comment appended to the denial result, and the **stop gate** armed; `Approved(comment, ...)` = CONTINUE but ADJUST — the original action is HELD (never run, even if `command` was edited), and the model is told to rework it to the comment and re-propose (the adjusted action is approved again before it runs). The **stop gate** (`_stop_gate`, arms via `_arm_stop_gate`, only denials arm it): eager models run another tool before addressing a denial, so while `self._pending_comment_response` is set every tool call is refused; the main loop clears it only on a **text-only turn** (not a same-turn text+tool: chatty preamble alongside a command would otherwise slip past), and that text-only turn ends the task — deny means stop. `run_task` resets the flag so it never leaks across tasks. Approvals never arm the gate (continue); the HOLD + re-approval is what keeps an unwanted original command from running. The step budget is **progress-gated (#108)**, not a flat cap: a step counts as progress when a tool call yields a (tool, args, result) tuple seen for the first time (reusing the loop detector's `repeats` dict — no extra model call, no timer). A progressing task may run past `max_steps` up to the unconditional hard ceiling `max(max_steps, HARD_STEP_CEILING=60)`; `MAX_STALL_STEPS` (8) consecutive no-progress steps stop it early. The loop ends three ways: a text-only answer, a cancel, or `_finish_stopped()` — reached at a stall, the hard ceiling, or when loop detection fires (identical call + identical result: warn at 3 repeats, stop at 5) — which runs one final no-tools turn so the model reports completion state instead of cutting off; the ceiling is never silently exceeded.

- **`backends.py`** — routes `--model` strings to a chat callable. Every backend (Ollama, Gemini, Claude API, OpenAI) is adapted to the *exact* `ollama.chat` calling convention (`chat(model, messages, tools, options, think, stream)`), so `agent.py` never knows which provider it's on. New backends must preserve this shape.
- **`claude_max.py`** — the exception: routes through the Claude Agent SDK / local `claude` CLI login. It strips Claude Code to bare inference and injects aish's own tools, so the approval gate still applies. Keeps its own session state. Three invariants added by #178 P0-4: (1) the SDK owns the loop, so the inner Agent's `run_task` — where per-task state normally resets — never runs; `ClaudeMaxAgent.run_task` therefore calls `Agent._reset_task_state()` (the SHARED extraction of run_task's top: stop gate, skill gates, `_run_meta`, `task_sources`, `_cancel` — add new per-task fields THERE, never inline in run_task, or claude-max wedges again). (2) The constructor has NO `**kwargs` sink — every capability the entry points pass is either kept on the wrapper (`on_message`, `on_token`, `status`, `max_steps`) or forwarded to the inner Agent (approvers incl. `approve_tool`/`approve_import`, trace/command/state sinks, steering callbacks, `semantic`, `aliases`); an unknown kwarg is a TypeError, so a new Agent capability can never silently no-op here. Plugin tools register on the SDK MCP server (`_current_tool_defs` = `TOOL_SCHEMAS + inner._plugin_defs`, refreshed per task by `_refresh_server`, mutating ones only when a tool approver is wired). (3) SDK tool handlers may run concurrently while the inner Agent is not thread-safe: `_locked_dispatch` is the single execution path — a `threading.Lock` around `inner._call_result(... inner._dispatch ...)`, which also emits the same tool_start/tool trace steps as the native loop and contains tool exceptions. Tested by `tests/test_claude_max.py` via a FakeSDK injected at the `_load_sdk` seam (no SDK package, no CLI, no network).
- **`approval.py`** — conservative parser classifying commands as read-only for auto-approval. Philosophy: only approve what it *positively* understands; anything ambiguous falls through to a prompt. Auto-approval is scoped to session roots (launch dir + `/add-dir` + directories the user trusted at a prompt); path arguments escaping them (absolute, `~`, `..`, symlinks resolved — including a plain relative token that IS an in-root symlink pointing outside, #178 P1-1; tokens naming nothing on disk are never resolved, so patterns/flags/future files can't false-positive) prompt even when allowlisted — `escaping_dirs()` names the escapes so the prompt/card can offer "trust this directory" (`Agent.trust_root`, session-memory only). Shell path operands also get `files.is_sensitive_path` on their RESOLVED target (mirroring the read_file sensitivity prompt), so `cat link-to-ssh-key` or an in-root `.env` prompts even when containment holds. The prefix allowlist has two lifetimes: `a`/"Always allow" is durable and file-backed, while `s`/"Allow this session" lands in `Agent.session_prefixes` and dies with the session (see the roots paragraph below — one rule for both halves of the scope). When touching this file, err toward prompting.

Model execution is **stateless**: every `run_command` runs in the project directory (`Agent.cwd`), a bare model-issued `cd` is rejected with guidance instead of executing (see `CD_NOT_STICKY` in `agent.py`), and excursions are `cd x && ...` subshells (`cd` is in `SAFE_COMMANDS` because it is subshell-scoped and root-checked). Only user actions move cwd: `/cd` and its alias `!cd` both move cwd AND re-anchor `roots[0]` (`Agent.rebase`). This keeps the model permanently anchored to the project directory — do not reintroduce model-driven cwd mutation.

**Auto-approval scope belongs to the SESSION, not the process (#176).** Both halves of that scope — the `roots` that bound auto-approval to directories, and `Agent.session_prefixes`, the command prefixes granted with `s` / "Allow this session" — live on the Agent and are reset by the SAME call, `restore_workspace`, so a session change drops them by construction rather than by someone remembering to. The approvers never own the prefix set: `cli.make_approver` and `server.make_web_approvers` both take a late-bound `get_session_prefixes()` returning the live set off the agent (same holder pattern as `get_scope`/`trust_dir`, because the agent is built after its approvers), and keep a set of their own only for an unwired approver in a test. `restore_workspace` CLEARS the prefixes and never restores them — unlike trusted dirs they are not recorded on disk, so resuming BACK to the chat that granted one asks again rather than inventing persistence the log cannot back. The persistent `a` allowlist is deliberately untouched by all of this: it is file-backed, shared by CLI and web, and outlives every session.

`restore_workspace(cwd, trusted)` is AUTHORITATIVE, never additive: on resume/cold-open it rebuilds `roots` to be EXACTLY that session's own workspace — its recorded `kind:"cwd"` (or `Agent.launch_cwd` when it never recorded one, matching the base the web gives a cold-opened session) plus its own recorded `kind:"trust_dir"` dirs, which `/add-dir` and an approval-prompt "trust this directory" both write. Both directions are bugs, because `roots` is what scopes auto-approval: a dir trusted in the chat you LEAVE must not stay auto-approvable in the one you land in (the CLI reuses ONE live Agent across `/resume`, so this leaked; the web builds a fresh Agent per cold open and never did), and a dir this chat DID trust must come back. `/new` re-anchors the same way (`restore_workspace(agent.cwd, [])` — you are still in that directory in this terminal, but the previous chat's grants stay with it). It sets state directly, never via `rebase`/`trust_root`, so restoring emits no fresh record (a replay feedback loop). The corollary: roots a PROCESS owns rather than a session — the web's uploads dir — must be appended AFTER the call, which is why `open_session` adds it below the restore block, not at construction.
**Origin-gated egress (#178 P0-2).** `Agent.origin` (constructor kwarg, default `"user"`; the server's `open_session` passes the session's origin, cli.py passes nothing) scopes two read-side capabilities to attended sessions. In a non-`user` session: (1) `web_search`/`read_url` (`EGRESS_TOOLS` — read-only locally, but their INPUTS leave the machine) hold on the existing `approve_tool` channel when they reach a host outside **provenance** — `_owner_hosts` (extracted by `_hosts_in_text` from owner-authored text ONLY: the task/trigger prompt in `run_task`, mid-task steering in `_inject_pending_messages`, `add_user_context`, and user-role turns in `load_history`; never tool results or fetched pages, which are exactly what an injection controls) plus `_approved_hosts` (hosts vouched on an earlier egress card; a plain approve caches the host for the session). `_egress_gate` mirrors `_dispatch_plugin_tool`'s #81 verdicts, passes the novel host as the card's `preview` (zero frontend change), and fails closed: no approver → `EGRESS_NO_APPROVER`, unparseable URL → gated. `_read_needs_prompt` routes gated calls out of the parallel read path so the gate can't be bypassed. (2) `_recall` drops the past-session archive search (knowledge entries stay) and says so in the result so the model doesn't retry. `user`-origin sessions are byte-identical to before — no new prompts. `TestEgressGate` in test_agent.py pins all of it.

- **`tools.py`** — `run_command` (approval-gated shell) and `read_docs` (auto-approved, so it takes only a bare command name validated against PATH — never a shell string). The denylist (unrecoverable commands blocked even with approval) lives here.
- **`files.py`** — pure `plan_*` functions compute (old, new, diff) without touching disk; `commit()` writes. The gap between plan and commit is where the diff is shown and approval obtained — nothing is written unseen.
- **`web.py`** — `web_search`/`read_url`, auto-approved but their inputs leave the machine, so every call is echoed and fetched content is wrapped in an untrusted-content banner. http/https only.
- **`session.py`** — append-only JSONL per session in `~/.local/state/aish/`: conversation (for `--resume`), audit trail of every command decision, plus `kind:"trace"` records — the structured activity-trace steps (the same dicts the web renders), logged from BOTH entry points via the agent's `step_log` sink so the trace is UI-agnostic and survives eviction/restart. Terminal-block framing (`kind:"cmd_start"`/`"cmd_end"`) is persisted the same way via the `command_log` sink. `reconstruct_events()` replays a logged session as the EXACT event stream a rich client emits live — `user`/`step`/`done` plus, for each run_command, its full `command_start → stream → command_end → tool` sequence — so a cold-loaded web session feeds the frontend identical events and renders an identical terminal block (no fallback path). The command's output rides on the `tool` step (not duplicated in the framing records) and is spliced back in as one `stream` with run_command's trailing `[exit code: N]` marker stripped (`_EXIT_MARKER_RE`), matching the live body where the code arrives via `command_end`; a legacy tool step with no framing gets a synthesized block. One `done` per task carries the final assistant text; it returns `None` for pre-trace logs, and the server falls back to a flat `history` blob then. `step_log`/`command_log` are orthogonal to the agent's `on_step`/`on_command_*` (rich-renderer hooks; `on_step` gates terminal chatter via `_note`) — the CLI wires the log sinks only, so it logs without changing its inline output. Its ranked excerpt search (`search_excerpts`, output hard-capped) backs the sessions section of the `recall` tool; the agent gets `state_dir` + `current_session` at construction and excludes the live session from results. `user_command_history()` (#104) aggregates the user's OWN successful `!` commands across recent sessions (only `decision:"user-direct"` records whose `cmd_end` reports exit 0 — model tool-loop commands never pollute the palette) and feeds the web terminal-mode autocomplete via the hello payload's `cmd_history`. `task_start`/`task_end` records (#164) bracket a web task on disk; `pending_task()` returns the unfinished one (with an `attempts` count = starts since the last end) and `interrupted_sessions()` lists them newest-first inside an age window — the durable half of restart recovery (see `server.py`). **Synthetic user turns (#171):** aish writes text into a conversation as `role:"user"` that the human never typed; the model must read it as the turn's input, so it is logged like any user message and the TEXT is the only thing a cold replay can classify it by. `synthetic_kind()` (markers `RESUME_MARKER` + `_NOTE_MARKERS`, which the producers build from or are pinned to by test — never an import of `server.py`, the higher layer) returns `"resume"` for a synthetic turn that really DID start a task: it replays as a normal `user` event carrying `synthetic`, so the frontend still runs the whole turn-management path and only swaps the blue bubble for a quiet system row. It returns `"note"` for the annotations that start no task — the `[aish: …]` loop/stall/step-limit nudges, the `/cd` + `/add-dir` announcements, console text shared into context — and those are SKIPPED entirely, because live they never reached the transcript at all (a `/cd` shows as a `workspace` marker) and one landing mid-turn also SPLIT that turn in two. A triggered session's opening prompt is arbitrary text with no marker to match, so it is identified positionally instead (`"trigger"` = the first user message of a non-`user`-origin log — the same message `handle_trigger` marks live). Because it classifies by text, logs written before #171 replay correctly too. The same classifier keeps aish's own notes out of `_derive_title`/`_derive_snippet`, so a chat opened with a `/cd` is no longer titled with the announcement that produced. `_parse` returns a **`ParsedLog` NamedTuple** (not a bare tuple) so log metadata can grow without rewriting every unpacking call site. **Parse caches (perf):** the read-only listing paths — `info`/`list_sessions`, `load_entries`, `_peek`/`pager_titles`, `user_command_history` — serve from stat-keyed module caches (`_PARSE_CACHE`/`_ENTRY_CACHE`, key `(mtime_ns, size)`), because re-parsing hundreds of JSONL logs on every session switch was the bulk of a swipe's server time and the parsing holds the GIL. The caches hand out SHARED objects, so they are for consumers that never mutate what they read: resume paths (`load_messages`, the CLI's `_parse` calls) stay on the raw `_parse` BY DESIGN — restored history flows into an Agent whose `_trim_tool_message` rewrites message dicts in place, which would poison a shared cache. `_by_recency` prunes cache keys for deleted files, scoped to its own state dir (tests run many dirs in one process). `user_command_history`'s command/exit pairing moved into `_parse` (`ParsedLog.user_cmds`) so it rides the same cache. **Auto-titling (#175):** `set_title(title, auto=…)` stamps the `kind:"title"` record with who chose the name, and `ParsedLog.title_auto` reads it back — that flag is what makes a hand-typed rename permanent (a record with no `auto` key predates the feature and was, by definition, a manual rename). `title_drifted(title, recent_text)` is the free lexical gate in front of the retitle model call: the fraction of the title's 4+-character words still present in the recent exchange, below `DRIFT_KEPT_RATIO` = drifted. Deliberately NOT embeddings — spending a model call to decide whether to spend a model call is a bad trade, and being wrong either way is cheap.
- **`prompt.py`** — the boxed input UI, built as a small prompt_toolkit `Application` (not `PromptSession`) because the footer-under-input layout requires it.
- **`server.py`** — `aish-web`: the same Agent behind a Starlette WebSocket instead of a TTY. `Bridge` is the core mechanism: `run_task` runs via `asyncio.to_thread`, callbacks emit JSON events through `call_soon_threadsafe`, and the approval callbacks block the worker on a `queue.Queue` slot until the browser answers — the approval gate is unchanged, only the transport differs. The process holds many open `Session`s (each its own Agent + SessionLog + Bridge + busy flag, capped at `MAX_OPEN_SESSIONS` with idle eviction) and serves many connections at once (**multi-connection, #102**): each socket is a `Client` (its own `ws`, `outbox`, `sender`, and independently-chosen `viewing` session), tracked in `WebServer.clients`; per-connection state that used to be singletons on `WebServer` (`self.ws`/`self.sender`/`self._active`) now lives on the Client. `Bridge._put` fans each event out to EVERY viewer's outbox (`Session.viewers`, owned by the bridge), and each Client's own sender coroutine drains its own outbox to its own socket — the transcript-append + all viewer-outbox pushes happen on the loop thread (via `call_soon_threadsafe`/`_show`), so no locking is needed (the invariant that kept replay snapshots race-free). Connections coexist WITHOUT preempting — `_attach` no longer closes the previous socket (the old single-client `CLOSE_REPLACED` path is gone); a bare connection (no `?session=`) lands on the default startup session (`WebServer._default`), a named one on `?session=`. Background sessions keep running, their events buffering into their transcript; switching a Client's view = hello + full transcript replay (`_show`), which is also what makes phone lock/unlock lossless. Control is **last-actor-drives**: every action handler calls `_claim(client)` first, stamping `Session.controller` and (when it changes) broadcasting a NON-recorded `role` event (`{controller, you}`) to that session's viewers; view messages (switch, files, jobs, dequeue, reconnect) never claim. There is no locked role and no disabled UI — the approval card fans out to all viewers, any may answer, and the asyncio loop serializes messages so exactly one `answer()` reaches the blocked worker (`Bridge.answer`'s pending-slot guard drops the duplicate). On disconnect (`_detach`→`_leave`) the Client leaves its session's viewers and, if it was controller, releases control (`role` → `controller:null`). `_evict_idle` never closes a busy session, one with viewers, or the default. **Session-row directory:** each row in the sessions list is labelled with its working directory (`_send_sessions` → `_row_cwd`) — read LIVE from the agent for sessions open in memory (it may have moved since the last recorded `/cd`) and otherwise from the log's last `kind:"cwd"` record (`SessionInfo.cwd`, picked up in `_parse`'s existing single pass), so the label no longer depends on the accident of which few sessions survived the `MAX_OPEN_SESSIONS` sweep. A session sitting in the server's launch workspace (`WebServer.base_cwd`, set by `create_app`) shows NO label: stamping the same path on every row is noise, so the chip's presence *is* the signal "this chat is somewhere else". The `role` event is never recorded, so cold replay re-derives control from live membership. The `active` property survives only as a representative-session helper for HTTP endpoints (no socket context) and tests; `/file` scopes to the union of all open sessions' roots. A session that fell out of memory (idle-evicted or after a restart) is reopened cold from its log and reconstructed into the same replay event stream (`SessionLog.reconstruct_events`), so its activity trace looks identical hot or cold. The vanilla-JS frontend lives in `aish/static/` (no build step, iOS-styled, inline SVG icons). Standalone PWA mode hides Safari's chrome, so a stalled socket has no browser refresh to fall back on (#18): `reconnect()` in `app.js` force-closes the current `ws` (even one still reporting `readyState OPEN` — a "zombie" socket the browser hasn't noticed died) and reconnects immediately, bypassing the backoff ladder. It's reachable from the session-title `⋯` menu ("Reconnect") and by tapping the existing `#connbar` "reconnecting…" bar itself. `requestNewChat()` wraps New Chat's `send({type:"new"})` to reconnect-then-retry when the socket is in a *detectable* dead state (CLOSING/CLOSED/CONNECTING) instead of silently no-op'ing; a zombie socket isn't detectable client-side, which is why the manual Reconnect control exists as the general fix. Pull-to-refresh was considered and skipped: `messagesEl` already runs a hand-rolled horizontal swipe-paging gesture with delicate vertical-vs-horizontal disambiguation (touchstart/touchmove/touchend near the bottom of `app.js`), and layering a vertical pull gesture on the same element risked fighting that logic for a case the menu/connbar controls already cover. **Pager ownership (post-#169 hardening):** the parked state has ONE owner — `parkTranscript`/`reconcilePager` (`// [UNPARK-START]…[UNPARK-END]`) are the only writers of `swipeInFrom` and of the transcript's resting transform, and `onReplay`/`ws.onclose`/`commitPage` delegate rather than hand-rolling a reset. A visible landing is **STAGED, not started**: `reconcilePager(landingFrom)` sits the transcript static at the entry side and starts the slide only on the next frame, so `onReplay` builds content and sets scrollTop on an element that is NOT transitioning — moving scrollTop mid-transform-transition left iOS WebKit compositing stale tiles (a fully black page, header/composer fine, until a finger-scroll repainted it). A short `settlePagerLanding` timer (`SETTLE_AFTER_MS`) owns the resting state whatever became of the animation AND nudges scrollTop ±1 to force tile rasterization; it stands down if a newer swipe committed. The `noop` replay landing never unparks — after a prefetched swipe it arrives mid entry animation and would jump-cut it. The rule the reconciler exists to guarantee: **every failure path degrades to "no animation", never to "no content"** — a committed swipe slides the transcript OFF-SCREEN on the promise of a landing replay, and that promise broke three separate ways (a reset inside `requestAnimationFrame`, which a hidden page never runs; clearing the inline transform, which only STARTS a transition a hidden page also never runs — so the element sat at the animation's start value while `style.transform` already read empty, i.e. the DOM lied; and a zombie socket that accepts the send and answers nothing, which no event announces). Hence: animate only when `visibilityState` is `visible`, a `PARK_DEADLINE_MS` watchdog armed at park time, and a `visibilitychange` reconcile that reads the COMPUTED transform (`transcriptDisplaced`). **Deck data has one constructor** — `deckCandidate()`; pager pages and `session_list` rows stamp `ts` in epoch SECONDS while a member works in ms, and converting per call site caused both the v1 seconds-vs-ms mis-seed and a seed source whose every page was discarded as undated. Adoption stamps a FRESH LEASE (`Date.now()`), not the chat's own age, which is what makes seeding source-agnostic. **Seeding is deliberately UNFILTERED and runs on `hello` as well as `session_list`**: `deckToPages` already falls back to the full source for an EMPTY deck, so any filter in seeding could only remove reachable pages — and a ONE-member deck is strictly worse than an empty one (it pins the pager to a single page), which is why `maybeSeedDeck` must not mark itself seeded when it adopted nothing. The 48h window stays as the EVICTION policy only. Curation is RECORDED (`curated`, set by the ✕) rather than inferred from an emptiness transition. Gesture recognizers yield explicitly: the pager sets `touchConsumedByTranscript` whenever it decides what a touch IS — standing down for a vertical scroll OR claiming a horizontal page-drag — and the window-level swipe-up respects it; geometry alone cannot tell a flick-scroll from an open-the-drawer swipe (the bottom zone overlaps the transcript), and the claim used to be one-sided (scroll only), so one diagonal flick could both commit a page switch AND open the drawer over it. Eligibility for a window-level gesture is decided at **touchstart**, never at touchend (a window listener runs last, after element handlers have already mutated the state it would read). **Rendered-view reuse (`// [VIEWCACHE-START/END]` in app.js):** a session switch replays the full transcript and rebuilds the whole DOM (markdown + hljs for every answer) — the slow half of a swipe on long chats. Leaving a CLEAN idle view (no live events since its replay, no pending cards, not busy, not mirror-painted) stashes its rendered nodes (`viewCache`, capped MRU), and a replay whose fingerprint (`replayFp`: event count + truncation + last event, capped) matches swaps them back in instead of rebuilding. Correct by construction: the transcript is append-only while a session is open, so any change moves the fingerprint, and every mismatch just rebuilds — the cache can make a switch faster, never wronger. Live events mark `viewDirty` at the `ws.onmessage` dispatch (deliberately NOT inside `handle()`, which the replay loop also calls — and which tests extract into bare sandboxes); `VIEW_SAFE_EVENTS` lists the types that never touch the transcript, so over-dirtying is the safe failure mode. `offlineFirstPaint` gained a `FIRST_PAINT_GRACE_MS` wait so a fast LAN replay wins the first paint outright instead of rendering every chat twice back to back. Pinned by `tests/js/test_view_cache.js`. `replayLanding` decides every landing: **"noop"** (same fingerprint, clean view, DOM present — the reconnect re-replay on every phone unlock and the second half of a prefetched swipe keep the DOM AND the scroll position), "reuse" (stash hit), "rebuild" (everything else). A session-switch hello resets `viewFp` so a cross-session fingerprint collision can never keep the wrong DOM. **Swipe-neighbor prefetch (`// [PREFETCH-START/END]` + server `_peek`):** after each hello settles, the client `peek`s one page left and right — a VIEW message answering `{type:"peek", name, events, truncated}` (no claim, no hello, nothing recorded; a miss answers `gone` ON the peek, never the resume error whose toast would blame the user). `commitPage` paints a warm peek synchronously after parking (currentSession moves first, openCachedSession's order, so the hello reads as same-session), and the authoritative replay no-ops on the matching fingerprint — instant swipe, nothing rendered twice; a stale peek just fingerprint-misses into a rebuild. `TestPeek` in test_server.py. **Passive transcript touch:** `#messages` carries `touch-action: pan-y` (inner code/tables/terminal opt back into `pan-x`), which lets the pager's touchmove listener be PASSIVE with no preventDefault — a non-passive touchmove on the scroller forced every scrolled frame to wait on main-thread JS, the biggest phone scroll-jank source; the browser's own gesture-start decision now enforces what preventDefault pretended to. Three guardrails the model cannot bypass: the WHEN test lives IMPERATIVELY in the tool description (create only when frequent + shell-fragile args + reliability; otherwise write a skill — never for read-only/simple/one-off); `Agent._create_tool` LINTS the drafted manifest in a temp dir and refuses to write on any error (structured feedback → correct-and-retry, so a broken tool can't land); and both files go through the normal `approve_write` diff gate (wrapper first — the executable, the critical thing to review — then manifest; a denial aborts without an orphan). The wrapper is chmod +x'd after commit and the plugin signature reset so the new tool is offered next step. `wrapper_lang` sets the file/shebang (sh|python); `scope` picks global (`~/.config/aish/tools`, backed up by the knowledge-git agent); `scope: project` is refused with a structured error while project discovery is off (a tool never discovered would be a silent no-op). It can also declare `preview:` (#157) — the parameter's description states IMPERATIVELY when to set it (args that are opaque identifiers, with the `reminders_delete` → `rem show <id>` example) and the `wrapper` parameter's description carries the contract the wrapper must honour (check `AISH_TOOL_PREVIEW` first, resolve + print ONE sentence, exit 0 WITHOUT mutating), because capability phrasing in aish's own prompts gets ignored by small models unless it is a MUST plus a concrete example. A non-bool value is written to the manifest verbatim rather than coerced, so the existing lint-in-a-temp-dir refusal catches it and the model gets structured feedback instead of a tool that silently promises a preview it never emits. Each tool is its OWN directory `<scope>/tools/<name>/` holding `TOOL.md` + the wrapper — the **manifest is written/approved FIRST** (the interface: review intent, then verify the code), then the wrapper. The tool description states this layout imperatively so the model stops inventing a flat `.json` layout (a real Gemini mis-narration this fixed). Out-of-project write cards show the full home-abbreviated path (`app.js` `relTarget`) so a global-config destination can't be mistaken for a file in the current project. **Knowledge reconciliation (#150):** after a tool is created, `_reconcile_candidates` deterministically finds skills/memories that mention a `prefer_over` command or share the tool's subject words, and `create_tool`'s RESULT appends an imperative instruction to UPDATE (repoint to the tool) or forget the ones describing the now-superseded manual way, while KEEPING orthogonal context — detection is code, the judgment + gated mutations are the model's, so stale guidance can't silently contradict a new tool. **Secrets (#142):** a manifest may declare `secrets: NAME1 NAME2` (env-var names); `execute()` resolves each via the Keychain (`secrets.get`) and injects them into ONLY that wrapper's subprocess env (`env=`), never into args — so a value can't leak into logs or the model's context; a declared-but-unset secret is a hard error, not a silent empty env. `create_tool` can populate `secrets:`.
- **`secrets.py`** — local secret store backed by the **macOS login Keychain** (#142), for the non-CLI integrations aish must hold a credential for (Fastmail/HA/ntfy/webhook — "auth stays with the CLI" covers none of them). Each secret is a generic-password item under service `"aish"` via `/usr/bin/security` (`put`/`get`/`delete`/`names`); a plaintext NAME index (values never) in the state dir backs `aish secret list`. Chosen (owner + Fable) over sops+age for being Apple-native, zero-dependency, and **structurally un-committable** — a Keychain item is not a file, so it can't be swept into the git-backed `~/.config/aish`. Managed with `aish secret <set|get|list|rm>` (`_secret_cli`, intercepted before the main arg parser; `set` reads via getpass). The honest security ceiling is FileVault + login-unlock: this defends against disk theft and accidental leakage (git, logs, model context), NOT a live attacker already running as the user.
- **`skill_import.py` + `import_skill`** — import a skill from a git repo or local path (#139). The untrusted surface is **imported skills** (their instructions + scripts are what the model would follow); tools need no import check because they're BUILT here via `create_tool` + diff-approval. `skill_import.stage()` only fetches (a shallow, read-only `git clone` that never executes the skill's code) + validates (real `SKILL.md`, name-checked) + collects the **text** files (binary assets skipped — not part of the trust surface). `Agent._import_skill` then presents ONE **consolidated review** via the `approve_import` callback (a 6th approver, wired from both entry points): the whole skill in a single decision — description, deterministic **risk flags** (`skill_import.safety_scan` — network/pipe-to-shell/sudo/sensitive-path patterns), and EVERY file's full contents rendered **syntax-highlighted** by `app.js`'s `buildImportCard` (reusing the vendored hljs via `highlightFences`; `kind:"import"` card) — NOT per-file diffs (that was approval-fatigue + all-green-diff-unreadable). On approve, all files install at once (`files.commit`, no further prompts); a denial installs nothing. The CLI reviewer (`cli.make_import_approver`) prints the flags + every file, one y/N. **CLI escape hatch (`aish skill <import|approve|list|discard>`, `cli._skill_cli`):** `import` STAGES to a quarantine dir (`skill_import.stage_to_disk` → `~/.local/state/aish/skill-imports/<name>/`, nothing installed) and prints the risk flags + path, so you review the files in your OWN editor, then `approve` (`install()`) moves them into the skills dir — the review-with-your-tools path for big skills. Safety is enforced in code, not by asking the model. Trustworthy public sources: `anthropics/skills`, `VoltAgent/awesome-agent-skills`.

Startup safety: launching either entry point from `$HOME` re-anchors the session to `~/aish` (`cli.default_workspace`, also used by `create_app`) so the home tree never becomes the auto-approval root; explicit `cwd` overrides are respected.

Web-only UI conventions the model is told about (in `web_usage_context`): quick-reply chips — `[Label](aish-reply://answer text)` links rendered as one-tap buttons by `app.js` — and the approval-card feedback field that produces `Denied(comment)`.

## Testing pattern

Tests script the model side instead of running one: `FakeChat` (see `tests/test_agent.py`) returns pre-canned responses shaped like the ollama library's, injected via `Agent(client_chat=...)`. Tool implementations are monkeypatched at the module level (`agent_module.tools.read_docs`, `agent_module.web.web_search`). Follow this pattern — tests must run with no model, no network, no real command execution. Frontend logic gets dependency-free Node checks in `tests/js/`: the REAL function is extracted from app.js by source markers and run in a `vm` context against a minimal fake DOM — the shipped code is tested, never a hand-copied duplicate. `tests/test_frontend_js.py` runs each script inside the pytest suite (skipped when node is absent).

**Tests must never reach the outside world, and "no network" includes the developer's phone.** `notify.configured()` reads the LIVE macOS Keychain, so any test that runs a triggered session to completion with no viewer reaches `_notify_done` and sends a REAL Pushover push — the restart-recovery tests did exactly that, firing two notifications on every `uv run pytest` (bodies `read it` / `sent the reply`, and no deep-link, since the test env sets no `AISH_PUBLIC_URL` — that missing URL is what identified them). The autouse `no_real_notifications` fixture in `tests/conftest.py` sets `AISH_NOTIFY=0` suite-wide, which short-circuits `pushover()` before it touches credentials or the network; tests asserting notification behaviour monkeypatch `notify.pushover`/`configured` themselves and are unaffected, and `test_notify.py` (which exercises the sender) opts out via its own autouse fixture with `urlopen` stubbed. The general rule: a module that reaches a real credential store needs a suite-wide guard, not per-test discipline — `test_suite_never_reaches_the_real_notifier` pins it.
