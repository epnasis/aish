# PDF export

`export.py`: local Markdown → PDF, media embedding, the markdown extensions the model's output actually needs.

*Split out of `CLAUDE.md`. Read this before changing the code it describes.*

- **`export.py`** — local Markdown → PDF for the web UI (#64): `markdown` → HTML → `xhtml2pdf` (pure Python, no system libs), the text never leaves the machine. Two shapes: one answer, or a whole session's FINAL answers — "final" is structural (an assistant message NOT immediately followed by a tool result), which cleanly drops thinking/tool turns. Media embedding (#133): local `![](path)` images inline as base64 only when the symlink-resolved path stays inside the caller's `image_roots` (since #188 that is `WebServer._image_roots`, the single boundary `/file` also serves under — anything outside becomes a captioned link card, never read); remote images, whitelisted Google static-map snapshots (needs `GOOGLE_MAPS_API_KEY`), and YouTube thumbnails ARE fetched at export time, each with a timeout + size cap and link-card fallback — and each through web.py's SSRF guard (#178 P1-4): `fetch_image` runs `web._require_public` and opens via `web._opener` (the redirect-re-checking opener), so a model-written `![](http://169.254.169.254/…)` can't fire a server-side GET at metadata/LAN targets when the owner taps export; a blocked URL degrades to the same link card as any other fetch failure. Heavy imports are deferred into the render function so server startup stays cheap. **Nested blocks in lists (#172):** neither library handles the markdown the model actually writes, so `_pdf_markdown_extension()` (built lazily, keeping `markdown` deferred) adds two pieces. `IndentedFence` is a preprocessor ahead of `fenced_code` (priority 26 vs 25), which matches a fence ONLY at column 0 — a code block indented under a list item was never recognised and leaked out as one run of inline `<code>` with its info string ("javascript…") in the text; it stashes indented fences as ready-made `<pre>` HTML *at their original indentation*, so the block parser still attaches them to their item and `_reflow_code_blocks` still splits them across pages (#147 holds inside a list). Its closing-fence regex allows the opening indent **+3 spaces and no more** — accepting any indentation let the inner close of a ` ```markdown ` demo end the outer block early and desync everything after it; a column-0 block is skipped wholesale as the stock extension's job. `FlattenLists` is a treeprocessor that rewrites every `<ul>`/`<ol>` into `<p>`s carrying a hand-drawn marker with a hanging indent (`text-indent: -Npt`) plus a `margin-left` continuation `<div>`: xhtml2pdf silently DROPS an `<li>`'s marker as soon as the item holds a block child (exactly what a loose/multi-paragraph item is) and renders sub-lists flat, so correct HTML still printed unnumbered. Continuation indents are RELATIVE, so a nested list simply stacks its own hang on the parent's. A `<p>` holding only a raw-HTML placeholder is never merged into a marker line — the postprocessor only substitutes a bare `<p>placeholder</p>`, so merging would leak the placeholder into the PDF. **Titling an answer export (#172):** the title (which is also the download name, via `safe_pdf_filename`) used to be the PROMPT the frontend sent along — a request ("test it with some difficult nested markdown"), not a description of the document. Now `handle_export_answer` takes no title at all: `WebServer._answer_title` asks the session's OWN agent (`?session=`, `agent.chat` called directly — no `run_task`, so the turn never enters the conversation or the log) for a 3-6 word title in the document's own language, off-loop via `asyncio.to_thread` under `TITLE_TIMEOUT`. `export.clean_title` unwraps what models pad a one-liner with (a `Title:` label, quotes, a `##`, a sentence of preamble — the LAST non-empty line is the title) and returns None for anything that isn't a title, which is the fail-safe: every failure path (claude-max, which exposes no `chat`; a transport error; a timeout; a rambling reply) falls back to `export.derive_title`, a deterministic local read of the answer's lead heading or first sentence. A title is a nicety and must never fail or block an export. The whole-session export still uses the chat's own title, which is what the sessions list shows. **Chat auto-titling (#175):** the chat title was `SessionLog._derive_title` = the first user message, which left a FORK wearing its parent's name forever (a fork copies the parent's log, so the "first user message" is the parent's) and a long chat named after its opening line. The load-bearing constraint is that the drawer lists sessions COLD (`list_sessions`) and the pager peeks them (`_peek`) — neither can afford a model call — so the name is computed at WRITE time and persisted as the same `kind:"title"` record a rename writes; the read path is untouched. `_maybe_retitle` runs at the end of a successful `_run_task` (never after a cancel — a stopped turn named nothing) and is gated by `_retitle_due`: never when `custom_title` is set and `title_auto` is False (a hand-typed name is the user's call, permanently); always when `retitle_forced` (set on a fork, so it earns its own name at its first turn); otherwise at turns 1, 3, 7, 15 … (`(turns + 1) & turns == 0`, logarithmic so it can never thrash — a name you navigate by must be stable) and, past turn 1, only when `session.title_drifted` says the chat left its current title. `_title_source` returns three things: the current title, the body to name from (**first two messages + last two, non-overlapping** — not the whole transcript, which would cost 50-100x the tokens for no better name), and the LATEST exchange alone for the drift check — measuring drift against the opening too would mean a chat could never drift from a title derived from that opening. `_model_session_title` mirrors `_model_title` exactly (bare prompt, no tools, called via `agent.chat` not `run_task`, so the naming turn never enters the conversation or the log) and every failure path — claude-max exposing no `chat`, transport error, timeout, a reply `clean_title` rejects — simply keeps the existing name. The new name is broadcast as a `session_renamed` event with **record=False** (a rename is UI state, not transcript; cold replay re-reads it from the title record), and the frontend needed NO change — it already handles that event. In tests, `FakeChat` answers titling calls (detected by prompt prefix) WITHOUT consuming the scripted response list and records them in `title_calls` rather than `calls`, so a response list stays a script of task turns; `title=None` (the default) means the backend declines to name anything, keeping every pre-existing test's behaviour identical.
