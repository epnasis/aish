# Session log — the append-only transcript

`session.py`: JSONL records, replay, activity, titling, redaction.

*Split out of `CLAUDE.md`. Read this before changing the code it describes.*

## - **`session.py`** — append-only JSONL per session in `~/.local/state/aish/`: conversation (for `--resume`), audit trail of every command decision — **all file writes serialize on the per-instance `_write_lock`** (#178 P2: the agent worker thread and the event-loop thread both write — rename, console-open audit — and an unserialized write on the buffered handle is a torn/lost JSONL line every reader silently skips; any NEW code path that appends to or rewrites the log must hold it, see `TestWriteLock`), plus `kind:"trace"` records — the structured activity-trace steps (the same dicts the web renders), logged from BOTH entry points via the agent's `step_log` sink so the trace is UI-agnostic and survives eviction/restart. Terminal-block framing (`kind:"cmd_start"`/`"cmd_end"`) is persisted the same way via the `command_log` sink. `reconstruct_events()` replays a logged session as the EXACT event stream a rich client emits live — `user`/`step`/`done` plus, for each run_command, its full `command_start → stream → command_end → tool` sequence — so a cold-loaded web session feeds the frontend identical events and renders an identical terminal block (no fallback path). The command's output rides on the `tool` step (not duplicated in the framing records) and is spliced back in as one `stream` with run_command's trailing `[exit code: N]` marker stripped (`_EXIT_MARKER_RE`), matching the live body where the code arrives via `command_end`; a legacy tool step with no framing gets a synthesized block. One `done` per task carries the final assistant text; it returns `None` for pre-trace logs, and the server falls back to a flat `history` blob then. `step_log`/`command_log` are orthogonal to the agent's `on_step`/`on_command_*` (rich-renderer hooks; `on_step` gates terminal chatter via `_note`) — the CLI wires the log sinks only, so it logs without changing its inline output. Its ranked excerpt search (`search_excerpts`, output hard-capped) backs the sessions section of the `recall` tool; the agent gets `state_dir` + `current_session` at construction and excludes the live session from results. `user_command_history()` (#104) aggregates the user's OWN successful `!` commands across recent sessions (only `decision:"user-direct"` records whose `cmd_end` reports exit 0 — model tool-loop commands never pollute the palette) and feeds the web terminal-mode autocomplete via the hello payload's `cmd_history`. `task_start`/`task_end` records (#164) bracket a web task on disk; `pending_task()` returns the unfinished one (with an `attempts` count = starts since the last end) and `interrupted_sessions()` lists them newest-first inside an age window — the durable half of restart recovery (see `server.py`). **Synthetic user turns (#171):** aish writes text into a conversation as `role:"user"` that the human never typed; the model must read it as the turn's input, so it is logged like any user message and the TEXT is the only thing a cold replay can classify it by. `synthetic_kind()` (markers `RESUME_MARKER` + `_NOTE_MARKERS`, which the producers build from or are pinned to by test — never an import of `server.py`, the higher layer) returns `"resume"` for a synthetic turn that really DID start a task: it replays as a normal `user` event carrying `synthetic`, so the frontend still runs the whole turn-management path and only swaps the blue bubble for a quiet system row. It returns `"note"` for the annotations that start no task — the `[aish: …]` loop/stall/step-limit nudges, the `/cd` + `/add-dir` announcements, console text shared into context — and those are SKIPPED entirely, because live they never reached the transcript at all (a `/cd` shows as a `workspace` marker) and one landing mid-turn also SPLIT that turn in two. A triggered session's opening prompt is arbitrary text with no marker to match, so it is identified positionally instead (`"trigger"` = the first user message of a non-`user`-origin log — the same message `handle_trigger` marks live). Because it classifies by text, logs written before #171 replay correctly too. The same classifier keeps aish's own notes out of `_derive_title`/`_derive_snippet`, so a chat opened with a `/cd` is no longer titled with the announcement that produced. `_parse` returns a **`ParsedLog` NamedTuple** (not a bare tuple) so log metadata can grow without rewriting every unpacking call site. **Activity is a property of the RECORDS, not of the file (#201).** "Last interaction" used to be the file's mtime, which cannot tell a chat that DID something from one that was merely looked at — and looking at a chat CAN append to it. A chat holding an image that fails to render (a remote host off the fetch whitelist, an evicted media file) had a `render_error` written on every replay, landing a second or so AFTER the client stamped "seen" (`markSeen`, `[SESSION-ENTER]`) — so `sessionUnread` saw activity newer than the look that caused it and the chat came back unread the moment you left it, permanently, with opening it to check being what re-armed the signal. `ParsedLog.activity_ts` is computed in `_parse`'s existing single pass by `_is_activity`, whose rule reuses a distinction this module already draws: **a record that renders nowhere is not activity** — `RENDERLESS_STEPS` is the one registry, so a future governance record inherits this instead of re-teaching it, and `model` is excluded for the same reason it is written lazily at all (it says which model a chat runs, never that it ran). `SessionInfo.activity` carries it (falling back to `mtime` for logs with no usable stamps — nothing may lose its place in the list), and every consumer of "when did this chat last do something" reads it: the `session_list` row `ts`, `pager_titles` (the deck ages members on it), and `/offline/session`'s `ts`. `_by_recency` deliberately stays on `stat()` — it is the cheap newest-first pre-filter and a superset — and so does the offline ETag, which genuinely IS about the bytes on disk. Pinned by `TestActivityIsNotAFileTouch`. **Parse caches (perf):** the read-only listing paths — `info`/`list_sessions`, `load_entries`, `_peek`/`pager_titles`, `user_command_history` — serve from stat-keyed module caches (`_PARSE_CACHE`/`_ENTRY_CACHE`, key `(mtime_ns, size)`), because re-parsing hundreds of JSONL logs on every session switch was the bulk of a swipe's server time and the parsing holds the GIL. The caches hand out SHARED objects, so they are for consumers that never mutate what they read: resume paths (`load_messages`, the CLI's `_parse` calls) stay on the raw `_parse` BY DESIGN — restored history flows into an Agent whose `_trim_tool_message` rewrites message dicts in place, which would poison a shared cache. `_by_recency` prunes cache keys for deleted files, scoped to its own state dir (tests run many dirs in one process). `user_command_history`'s command/exit pairing moved into `_parse` (`ParsedLog.user_cmds`) so it rides the same cache. **Auto-titling (#175):** `set_title(title, auto=…)` stamps the `kind:"title"` record with who chose the name, and `ParsedLog.title_auto` reads it back — that flag is what makes a hand-typed rename permanent (a record with no `auto` key predates the feature and was, by definition, a manual rename). `title_drifted(title, recent_text)` is the free lexical gate in front of the retitle model call: the fraction of the title's 4+-character words still present in the recent exchange, below `DRIFT_KEPT_RATIO` = drifted. Deliberately NOT embeddings — spending a model call to decide whether to spend a model call is a bad trade, and being wrong either way is cheap. **A chat has an eraser (#202).** The transcript was append-only and replayed whole, so anything that landed in it was permanent short of deleting the chat or hand-editing JSONL with the server stopped — a probe fired at the wrong chat (#201), a message an autocorrect Return sent half-typed, a secret pasted into the composer. `redact_turn(turn)` is the removal, and the unit is the **TURN**, never one bubble: an answer repeats what it was asked and a command echoes the argument it was given, so half a turn is not a removal. It is a REAL delete plus a POSITIONED tombstone rather than the issue's hide-only tombstone — the records leave the file and a dated `kind:"redact"` record takes their place AT THEIR POSITION, so the removal stays auditable (when, which turn, how many records) while the text is gone from disk, which is the only answer that works for the pasted-secret case. Three details are load-bearing. (1) The cut runs from the turn's `task_start`, not its user message: `task_start` is written FIRST and carries the prompt VERBATIM, so cutting from the message would leave a copy of exactly what was removed — and would strand an unmatched `task_start`, which restart recovery (#164) reads as a task to resume. The same walk-back decides the END, or the removal takes the NEXT turn's `task_start` with it (found in browser verification, pinned by test). (2) Turns are NAMED: `SessionLog.message` mints a `turn` id on every user record and `reconstruct_events` carries it on the `user` event, with `_turn_id` falling back to the record's LINE INDEX for logs written before ids existed — which is every chat holding a message someone wants gone. The id is minted by the SERVER (`_turn_event` → `Session.open_turn` → `LogRef.pending_turn`) so a LIVE turn is removable too; the message you most want back is the one you just sent, and a log-minted id would only exist after a cold replay. (3) `Redaction.occurrence` says WHICH identically-worded turn it was, because the live Agent's messages hold no ids (its dicts go straight to the backends) and two turns saying "ok" would otherwise be indistinguishable — dropping the wrong one from the model's context is the one thing this must not do. A redaction IS activity, unlike the renderless records #201 exempted: every device mirrors the transcript and only refetches a session whose activity stamp MOVED, so an unmoved stamp would leave the removed text in IndexedDB on each of them — hence `_parse` now takes the LATEST activity stamp rather than the last one in file order (a rewrite made file order stop meaning chronological order). An AUTO title is re-derived and its stale records DELETED (a model-written name is a summary of the conversation and can quote the very text being removed); a hand-typed title is the user's own words and is left alone. Pinned by `TestRedaction`.
